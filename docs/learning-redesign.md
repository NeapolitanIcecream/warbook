## 自对弈的准确定位

对手池提供训练分布；学习器须在这个分布中找到更有效的响应。把 checkpoint 加入池不会自动完成后者。还要处理非传递关系、遗忘和探索：只按总胜率保留冠军可能丢掉能暴露主线弱点的专家。

当前是固定参考加对方两臂当轮模型的有界交替适应，不是不断积累所有有用历史策略、按弱点分配训练的完整 league。已保存模型也不等于它们正在被采样。先前的正向与退化结果说明有限学习存在，尚未形成稳定能力积累；不能把胜过当前对手或池内排名提高直接解释为通用实力提高。

[PSRO](https://arxiv.org/abs/1711.00832)将学习对策略混合的近似最佳响应与对手分布选择分开；[AlphaStar 官方说明](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)另强调专门暴露弱点的 exploiters、策略多样性和模仿先验。它们支持设计原则，不保证本项目的 PPO 自举收敛。

## 建议的控制边界（待 Pro 复核）

| 层次 | 决策/职责 |
|---|---|
| 可学习战略 | 经济与生产/科技安排、侦察区域、任务与兵力分配、多编组协调、进攻/回防/撤退和任务终止 |
| 任务条件战术 | 局部展开、接敌、目标选择、GI移动/部署、短撤等；初期可沿用规则，装甲微操课程需要在此开放真实可学习控制 |
| 命令执行 | 引用/归属、合法性、队列和前置约束、原生命令持续执行、失败/完成反馈；以后可适配RPA |

RPA是操作出口，规则是决策方法。若微操层永久固定为规则，训练装甲场景不能让战略模型发明菜单外微操。战略全局撤回和战术任务内避险须有明确归属，执行器不能再用旧风险门槛否决合法战略，也不能暗中用固定经济规则补齐模型的决策。

输入应补齐实体/相对几何、地图连通区与通道、合法敌情记忆、任务与经济状态，使用可处理可变对象数的共享编码和有限记忆。候选草案是实体/区域编码加小型循环状态、分解的生产和任务动作头；避免枚举目标×兵量×科技×所有任务的笛卡尔积。参数规模和头的细节尚未定，不把“所有战略”误写成“一个巨大的扁平动作表”。

## 短场景：值得开展的环境工程

目标是增加有意义交互的比例、缩短行为到结果的间隔，同时让微操获得相应控制权。先调查装甲互战/桥头接敌，再扩到增援与多路防守、中盘经济取舍。随机化兵数、初始相对位置、支援、地形和对手，训练、验证按场景来源分组；局部消灭敌军并不替代整局目标。

三条路径分别处理：

1. **自定义地图/INI初始化**：本次源码复核 `MapFile.fromString` 调用 `readVehicles/readInfantries/readStructures`，`PublicApi.init` 加载资源目录和当前工作目录的独立文件，offline创建从VFS/RFS读地图。这是实现入口的源码证据，尚未运行验证预置单位的玩家归属、出生、胜负或回放，不声称已能直接启动10v10。
2. **正常开局的前缀控制器，条件满足后切换学习器**：沿已有真实引擎推进，不依赖恢复接口。需要暖启动合法记忆/任务状态；前缀仍消耗模拟时间，不能冒称精确相同中盘或免费reset。
3. **真实中盘/残局恢复**：当前公共API没有已验证restore/takeover。完整状态还涉及命令队列、冷却、经济、随机源、可见性和双方控制器记忆。若前两条不足，开展有界适配；保存单位坐标/血量不是精确恢复，机械播放原对手后续命令也不是闭环对手。

普通开局地图先验不能不加审查地用于预置敌方对象的场景，须避免从通行信息泄漏隐藏布置。规则/武器/寻路沿 pinned 引擎；短场景训练成果最终接回正常完整局，观察迁移而非只报场景胜率。[SMAC](https://arxiv.org/abs/1902.04043)是微操场景训练的一手先例，不等于Chrono Divide已经具备同样环境能力。

## 容量：先分开四种问题

1. **表示限制**：若两个合法可区分局面被编码成相同输入、相同菜单，但各自需要相反动作，任何规模的该输入模型都无法分别选择。等概率二状态、选对得1的例子中，最优期望至多1/2。这是信息损失的下界，不是参数不足。
2. **近似能力**：在输入可分、动作可执行且标签可靠的有限诊断集上，检查当前网络能否拟合关键条件化决策；训练误差低只证明这组任务可表达。高误差还须排除优化失败和标签冲突，不能立刻判容量不足。
3. **优化与样本**：同一网络多起点/更充分拟合可帮助辨认优化问题；训练集与来源隔离验证的差距、随数据量变化的曲线可帮助辨认泛化和覆盖问题。PPO loss非平稳，不是容量测试。
4. **在线探索/信用分配**：若同架构能拟合有用策略，在线RL仍到不了，应重点查采样和奖励归因。容量确认仍可能需要一次受控规模比较；参数数、梯度范数或理论通用逼近性不能单独证明足够。

理论能给必要条件与特定函数类的界，不能直接算出RA2战略需要多少参数。消费级预算下优先改变信息表达、共享结构、时序和推理频率；较大训练教师/蒸馏只在有收益后考虑，不把它作为无限扩容的理由。
