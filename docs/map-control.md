## 结构问题

现有战略、战术、生产分层可以保留。缺口在它们共享的战场模型和任务表达：

| 当前做法 | 造成的问题 | 改造职责 |
| --- | --- | --- |
| 地图主要是出生点、格点和已探索局部寻路图 | 不知道通道、矿区与前沿的关系；来援估计主要用直线距离 | 从原始地图建立静态先验，再叠加合法动态观察 |
| 侦察优先找出生点、随后扫未知格点 | 缺少“查明对手屯兵/产能/某条来路”的任务 | 战略声明当前缺的情报，侦察选择能回答问题的观察位置 |
| 敌单位失联统一保留三十秒 | 已毁对象与真正失联对象混在一起；战果转化滞后 | 区分可确认战果、当前接触和不确定记忆；确认方法必须满足可见性边界 |
| 作战计划主要绑定一个目标对象和目的地 | 不能持续保持通道或矿区，也缺少进攻停止后的局部驻守 | 作战任务包含区域目标、推进路线、支援/退让位置及终止条件 |
| 取消攻打目标即触发返家恢复 | 小幅风险变化变成跨地图撤退，并让出已有位置 | 分开继续接战、当地重整、退一层和全局撤退 |

此外，当前报告中后续预备队的风险评估会覆盖取消原进攻的判断。新任务模型应保留状态转换的直接理由，避免再靠大段常规输出猜撤退原因。

## 最小实施范围

1. **静态地图先验与动态敌情分开。** 先复用现有 ngraph，把已安装原始地图中的通路、坡道/桥、候选出生区和初始矿区用于开局规划；实时敌方部署、剩余矿量和桥梁变化仍来自合法观察。不能用运行中全图查询冒充赛前地图知识。新信息条件需显式记录、同条件重测对照。
2. **侦察服务于一个具体问题。** 第一项是探清敌家主要建筑及其出兵、集结空间；之后根据准备进攻/担心来袭的位置补情报。完成条件是获得这些信息，不能仅以狗走了多远或揭开格点减少验收。
3. **给现有 Operations 增加区域承诺。** 先支持基地通道、在采矿区、敌基地前沿三类区域；歼敌后可以继续守住前沿并接纳增援。重新评估“攻打某建筑”时，同时选择该区域中可持续执行的行动。
4. **按原因与空间层级撤退。** 短暂情报变化可触发当地重整；真正失去局部优势才退向可支援的位置；回基地是有条件的更深撤退。评估双方到达当前战场的路径时间，不把所有附近单位同时算成已经参战。

首轮验收只围绕本局三个反例：敌家屯兵盲区、18:07 战果/撤退冲突、撤退后前沿与矿区的责任。先做局部决策检查，再跑原主线与新压制两条路线的完整局；最后扩大固定池比较。地图与战场模型可共享，主线和压制保留不同的进攻/经济承诺，不要求引入大模型、RL、通用多层规划框架或重写引擎。
