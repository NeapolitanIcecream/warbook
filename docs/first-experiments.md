# 首批判别实验与失败预演

状态：2026-09-15 的前期分析。**下列卡片均未完成引擎实验，没有新增游戏结果。本文提出设计与分析输入；已有源码探针按其声明范围单独引用。** API 能力以 [环境审计](environment-audit.md) 为准，通用评分与统计规则见 [评估协议](evaluation.md)。本文补充“接下来测什么，以及什么结果会改变路线”。

## 失败预演：遵守规则，为什么仍可能做不出好 AI

假定团队保留完整回放、不偷看测试集、不谎报胜率，也按规定做局部与整局比较。以下失败仍然可能发生：

| 失败路径 | 为什么已有纪律仍不充分 | 最早值得看的信号 / 实验 |
| --- | --- | --- |
| 输入字段都合法，但候选计划已被隐藏状态筛过 | 对 actor 输入的有限检查，没有覆盖产生 mask、候选或路径评分的上游代码；答案不一定以敌方字段出现 | 相同合法历史下，只改裁判记录就改变候选集合；E01 |
| 为避免泄漏，把合法、重要的信息也删掉 | 保守协议可以自洽却使任务不必要地困难；例如直接套用其他 RTS 的观察裁剪，丢掉本引擎允许保留的信息 | 合法事件在表示里无来源或过早失效；E01、E05。协议受限不等于算法能力差 |
| 有真实收益，但优化错了层 | 换模型同时改变命令频率、去重或计划保持时间；整局确实改善，却把执行器收益误认为模型理解了战术 | 候选选择不变，发送命令变少后已有引擎任务更稳定；E02、E03、E07 |
| 输入、动作、最终胜负都记录正确，指令仍来自过时世界 | 日志的单条记录各自正确，但异步计算完成顺序与观察、任务代次错位；平均延迟还可能掩盖关键时刻的长尾 | 旧目标/旧任务在新任务之后被执行，平时正常而交战崩溃；E04 |
| 真实历史恢复了，决策问题仍不一样 | 只回灌观察，漏掉实际动作、任务承诺或随机状态；新控制器还可能被接到它自身不会到达的状态 | 接手瞬间重新侦察、重复花预算或改变任务，之后又恢复正常；E05 |
| 每项局部研究都严谨，但专攻容易测量的次要问题 | 从末端损失出发不断改善微操，真正差距却在更早的生产、到场时机或候选计划；每次局部失败都能写成合格报告 | 多轮排除了原因，却未改变下一步决策或整局行为；E06、E10 |
| 独立文件里的完整局并不代表独立初始化 | 当前源码使用秒级时间戳生成初始化随机性；同批创建可能共享随机条件。重复对局、完整日志和固定版本本身不解决相关性 | 相同时间桶/起点模式成簇，A/A 比较也随批次或顺序移动；E09 |
| 对手来自不同仓库，行为却只有一种 | 来源多样性不保证战略多样性；所有对手都可能执着追逐同一支部队，因而无法惩罚放弃经济目标的打法 | 多个对手对撤退都只追不转攻；E06、E10 |
| 所有候选都输了，被解释成“这里不值得学习” | 有限候选、错误介入时点、固定续局策略共同限制结果；阴性实验正确，但路线推断过强 | 提早介入或允许部分撤退后，原问题的可执行选择才出现；E10 |

这些反例不是对现有实现的故障诊断。有限测试不可能证明所有路径正确；应优先覆盖当前实际使用的路径，并在新增能力或新失败出现时扩充。也不要反向要求“先证明协议完备才能打第一局”。

## 使用顺序：实验菜单，不是十道开局门禁

| 时机 | 本轮只需做的内容 |
| --- | --- |
| 首局前 | E01 的最小边界检查，仅覆盖首版真正使用的输入与控制路径；未使用 mask、搜索、循环网络就不为它们先建系统 |
| 首局中及紧接的回放核查 | E02、E03、E08 采集少量存在性证据；没有自然出现的条件就记“未覆盖”，不强行造场景。E09 只顺手记录初始化与批次信息 |
| 观察到问题才做 | E04–E07、E10 按触发条件选一至两项。E09 的 A/A 比较在开始解释细小 A/B 收益或发现初始化异常时做 |

首局仍以正常开局、正常推进、能解释结束原因为目标。卡片中的对照需要多局时安排后续新对局，不要求一局同时完成全部干预。用 [实验模板](../templates/experiment.md) 记录实际执行的卡片即可，无需复制全文。

## E01 — 白名单之外是否仍传入答案；白名单是否误删合法信息

- **时机 / 触发：** 首局前完成最小路径检查；接入新字段、mask、搜索或事件通道时扩充。
- **准确前提：** 已声明首版信息协议，适配器能接收记录并输出 actor 输入/候选。这里的 mask 是自建接口概念，不假定原生 API 提供。只需普通数据记录，不需要修改引擎状态。
- **对照与替代法：** 构造合法历史完全相同的两份适配器输入记录，只在标明为裁判专用的隐藏字段或全局事件上作差异；固定策略随机状态，比较完整 actor 输入、候选、mask 和输出。再加正对照：改变一项按协议应保留的合法事件，核对表示是否正确更新。缺真实轨迹时用手写记录测接口隔离，明确它不是可达游戏状态证明。
- **预期可观察后果：** 裁判专用变化不改变 actor 可见路径；合法事件按协议进入表示并保留正确时效。可以记录上游访问来源，不能只看最后动作碰巧相同。
- **否定条件：** 隐藏记录改变候选可用性/评分，或合法事件被无故丢失。输入不变但决策相同不能排除尚未覆盖的泄漏路径。
- **结论边界：** 通过只支持所覆盖转换的隔离与完整性；不证明人类等价观察、全部 shroud 语义或真实世界对偶可达。正对照不要求动作一定改变。
- **失败后决定：** 先修对应转换或去掉尚不可信的输入路径；记录受限协议继续普通首局。若删掉的是任务必要信息，先解决该协议问题，再评价依赖它的策略能力。

## E02 — 不发命令、保持任务与显式 Stop 是不是同一件事

- **时机 / 触发：** 首局中记录实际出现的情况；想把 no-command 当收益基线时补齐对照。
- **准确前提：** 正常对局、合法拥有的单位、已可调用的命令接口及状态记录。`Stop` 的具体效果仍待实测；没有“关闭引擎自主行为”的既有前提。
- **对照与替代法：** 区分从未下令、已有 Move/Attack 等任务后不再发新令、显式 Stop、固定时序控制四种历史。观察自然遇敌或移动，不通过 API 生成敌人。同一单位先后切换可检验某行为存在，但不同历史不能当作严格收益配对。
- **预期可观察后果：** 记录新命令数量、原目标/任务、实际位移与开火时间线，区分继承任务、自主行为和新策略的增量。
- **否定条件：** 标为“无行为”的基线实际继续移动/攻击，或所谓学习增益在移除新决策后仍由原命令产生。若没有遇敌，只能说明该段未观察到攻击，不能判定不会自动攻击。
- **结论边界：** 只说明所测单位、命令历史和规则下的行为；不把某一种 no-command 解释推广到全部单位。Stop 也不是天然静止的真值对照。
- **失败后决定：** 修正基线名称、状态记录与收益归因；重新比较现有默认行为的增量，不急于训练替代一个尚未理解的控制器。

## E03 — 策略意图是否真的成为游戏动作

现有 [orderUnits 源码方法探针](references/order-units-probe.json) 在声明的 mock 条件下，发现缺失对象可留下选择动作而不提交预期命令，零坐标也会进入不同参数分支。这是方法分支证据；既没有运行游戏动作，也没有证明真实地图存在相应合法零坐标。它使“调用成功但未执行意图”成为值得优先排查的具体解释。

- **时机 / 触发：** 首局中检查一个生产/部署动作与一个移动/攻击动作；重复命令、卡住或输出不足时扩展。
- **准确前提：** 可记录观察 tick、任务代次、策略选择、实际发送命令和后续状态；API 的 void 返回不当作执行成功回执。
- **对照与替代法：** 先检查单次意图的后置条件，再在后续正常对局比较“意图变化时发令”和“按固定频率重复发同一意图”。无需摆单位；记录实际条件。不要把不同单位或不同时间窗口的差异直接解释成重复命令的因果效果。
- **预期可观察后果：** 展开、开始/完成生产、位移或攻击产生可追溯的状态变化；发送与实际生效间隔可见。无效目标、控制权覆盖、资源变化等有明确解释。
- **否定条件：** 日志声称执行但后置条件不存在；改变重复频率就改变行为，而策略层仍被当作唯一干预；两个模块交替覆盖同一单位。
- **结论边界：** 请求后恰有伤害不等于该请求造成伤害，也可能来自既有任务。有限检查仅确认对应语义，不预先断言反复下令一定打断或提高输出。
- **失败后决定：** 修命令仲裁、发送时机或效果确认；用相同高层意图复测。正确性修复可先保留，棋力声明另由完整对局支持。

## E04 — 旧计算结果是否覆盖新任务

- **时机 / 触发：** 出现异步推理、工作线程、远程模型或错序日志时才做；同步首版无需先实现异步设施。
- **准确前提：** driver 能记录生成/返回/发送 tick、观测版本、单位控制权和任务代次。已审计的 bot 回调不会自动 await；延迟由自建调度器显式处理，不能依赖改变回调签名。
- **对照与替代法：** 对同样的决策输入比较同步结果与受控延迟/错序完成的结果。先用手写事件序列测试队列：旧任务计算尚未返回时新任务已接管、目标已失效、资源承诺已变；这是调度测试，不是引擎模拟。需要看实战影响时再在普通对局注入延迟。
- **预期可观察后果：** 失效的旧控制权或前置条件阻止命令覆盖；日志能解释接纳、丢弃或重新计算。仍然有效的长期计划可继续，不能把“较旧”机械等同“错误”。
- **否定条件：** 后返回的旧任务覆盖新任务；计时仅记录模型耗时而遗漏排队/等待；丢弃所有延迟结果又使关键任务长期没有可执行方案。
- **结论边界：** 队列测试证明调度规则，不证明游戏中的最佳时限。平均延迟相同不代表关键交战时刻的行为相同。
- **失败后决定：** 先采用同步控制或明确的任务代次、前置条件与回退策略；待调度正确再比较模型。将迟到率与实际作用分开，避免用更快但无用的输出冒充改善。

## E05 — 记忆预热是否重建了接手所需的上下文

- **时机 / 触发：** 引入有记忆策略、中途切换控制器、回放监督或前缀重建时才做。
- **准确前提：** 可记录合法观察、实际动作/效果、任务和预算承诺；控制器的随机源可记录。离线重放自己的输入记录即可开展检查，不要求 replay takeover。真实接手需要自建 driver 在正常新对局内切换控制，能力另行验证。
- **对照与替代法：** 比较同一候选 B 从头旁路处理真实历史，与 B 从记录重建该历史后的状态/下一步输出；B 的旁路输出不发给游戏。再比较完整历史、只给最后一帧、只给观察却漏掉实际动作三种条件。候选 B 使用自身状态结构，不能复制 A 的隐藏状态。
- **预期可观察后果：** 相同合法输入历史与随机状态能重建 B 的有关记忆；若 B 依赖动作或承诺，遗漏它们时应能检查出预期状态差异，而不只看到最终动作不同。不依赖这些字段的控制器无需强行产生差异。
- **否定条件：** 完整记录仍无法重建；接手后重复预算、错误认领单位或把旧任务当新任务；所谓“完整历史”混入 B 未实际执行的旁路动作。
- **结论边界：** 重建成功只证明条件历史下的控制器一致性，不证明完整引擎恢复。A 产生的历史可能不在 B 自身常见分布中；合法接手收益也不等于 B 从开局自主对局的收益。
- **失败后决定：** 修正历史 schema 或采用明确定义的保守接手状态；若该能力暂非必要，继续从开局运行 B。不要为解决状态重建而阻塞普通完整对局。

## E06 — 保存部队的收益是否由任务目标付账

- **时机 / 触发：** 撤退、追击、守备或经济保护的局部指标改善，却未带来整局改善时做。
- **准确前提：** 有真实任务、目标位置、损失与时间线；对手至少能继续执行其正常策略。不存在精确分叉时，用新对局中冻结的规则干预，不制造相同状态标签。
- **对照与替代法：** 比较偏保存部队、简单留守、按任务中止条件行动。至少检查一种继续追击和一种可能转攻经济目标的响应式对手；没有现成对手时先审查记录是否覆盖该反应，明确缺口，不把原录像命令当新反应。
- **预期可观察后果：** 分别观察部队损失、保护目标是否存续、采矿/生产中断、重新接敌时间与最终结果。短窗口内撤走后仍存活，而稍后目标丢失，必须在记录中连起来。
- **否定条件：** “守住”只是测量窗口早于敌方到达；部队保存来自把风险转给矿车/建筑；优势仅在执着追逐的对手上出现。
- **结论边界：** 目标损失不自动说明撤退错误，可能是合理交换；有限后续窗口也不能代表终局。这里检验代价与上下文，不预设人类偏好的答案。
- **失败后决定：** 改任务表达、时间窗口或对手覆盖；评分变动时重测双方。若明确代价后收益仍在，保留非常规打法；否则调整目标或控制策略。

## E07 — 改善来自决策器，还是命令执行与续局策略

- **时机 / 触发：** 首次准备把收益归因于一个模型、规划器或局部模块时做；纯正确性修复无需承担学习归因声明。
- **准确前提：** 能区分候选选择与执行器，保存实际模块版本和续局条件。不要求反事实分叉；各组合从正常开局运行。
- **对照与替代法：** 有两个因素同时变化时，比较旧/新决策 × 旧/新执行器的四种兼容组合，保持信息与预算可比；若接口不兼容，先记录只能比较系统整体。对小窗口干预明确何时交回哪个续局策略。用同一记录的意图旁路检查，可先排除“选项相同，只是去重变了”。
- **预期可观察后果：** 观察候选、选择、命令与任务后果在哪一层开始分歧；执行器单独带来的收益、决策器增量与两者交互分别可见。
- **否定条件：** 新决策 + 旧执行没有预期行为变化，旧决策 + 新执行已产生改善；或所谓局部策略只在特定续局器接手后才有收益。不能只拿用于选优的同一批结果再作独立验收。
- **结论边界：** 本卡的新对局比较不提供单次行动的精确反事实，seed 本身也不足以提供；足够的随机分配与分层比较可以支持模块层面的平均效果。有限组合的负结果不证明该模型家族无价值。
- **失败后决定：** 把收益归给有证据的层，保留真正有效的工程改动；必要时修改模块接口或研究交互。只有已执行轨迹时，不为未执行候选补造效果标签。

## E08 — 赢的是游戏，还是结束条件与汇总器

- **时机 / 触发：** 首局记录自然终局、截断和异常的区别；第一次改汇总器、结束规则或报告算法时做记录级检查。
- **准确前提：** driver 能记录停止原因与可获得的终局/异常证据，分开最大 tick、墙钟限制、bot 异常与运行器异常；API 未暴露足够信息时必须允许“结束原因未确认”。`isFinished()` 也可能表示 turn manager 错误，不能直接当作自然终局；详见 [接口契约](interface-contract.md)。报告测试只需手写 manifest，不需要引擎。
- **对照与替代法：** 给汇总器输入“自然获胜”“有资产优势但到时截断”“模型报错后未完成”“回放解析失败但原运行有结果”等不同记录，检查预先声明的计数方式。兼容回放中核对少量结束状态；回放加载失败先标兼容性问题，不抹除原运行。
- **预期可观察后果：** 无自然胜负的记录不凭存活或资源优势变成引擎获胜；全部启动局都有去向，报告有效样本数、故障数和排除规则；游戏时间与计算时限分开。
- **否定条件：** 把到时截断自动记为引擎获胜；只对成功完成的局算胜率却声称无条件竞争力提高；同一原记录换显示名称就改变计分；改规则后拿新分数减旧协议的基线。
- **结论边界：** 手写记录只测结束分类和报告逻辑，不证明实际驱动能正确识别终局。如何评价超时是协议选择，需明确而非默认有唯一答案。
- **失败后决定：** 修运行器或报告，并按一致规则重算可用原记录；需要新信息或结束时间变化时重跑双方。先撤回错误的收益归因，再决定是否需要新的策略工作。

## E09 — 没有 seed 控制时，能否区分策略变化和运行批次

- **时机 / 触发：** 首局顺手记录元数据；开始解释细小 A/B 收益、增加并发或看到起点/结果成簇时做 A/A 检查。
- **准确前提：** 可从正常新对局记录创建时间、进程/批次、实际地图/出生位、策略版本、终局和故障；策略分配使用独立且有记录的随机源。不假定 `createGame` 支持 seed，亦不假定起点摘要等于完整初态。
- **对照与替代法：** 同一个基线分成标签 A/A，按预定方案交错、随机分配到运行时段；检查调度、初始化和丢局是否随标签变化。真正 A/B 也按相同安排运行。无运行资源时，用手写成簇 manifest 检查报告是否错误地把同源行当独立证据，不能据此声称初始化已验证。
- **预期可观察后果：** 标签本身无行为差异；能够识别同批相关风险，按预先定义的时间/批次与地图条件报告。小样本先给原始计数、分布和限制，避免自动产生精确区间。
- **否定条件：** A/B 标签决定启动顺序、筛掉哪类故障或特定出生位；复制记录增加“独立样本数”；同批依赖未经说明却按独立局计算不确定性。单次 A/A 差异本身不证明工具有 bug，也可能是随机波动。
- **结论边界：** A/A 未见差异不证明独立性；相同初态摘要不证明内部随机状态相同。事后分层不能消除所有未观测混杂，缺乏重叠条件时不能勉强给出比较。
- **失败后决定：** 先纠正分配、记录和汇总，收集更多独立批次并限制结论。只有初始化噪声持续阻碍一个有价值的比较时，再考虑开发 seed/出生位适配器。

## E10 — 值得学习的选择是否被候选、时机或对手限制掉了

- **时机 / 触发：** 多轮优化无行为收益、准备开始一个学习模块，或声称“没有可学习空间”时做。
- **准确前提：** 已知一个真实失败，可提出少量合法、可执行替代方案及介入触发条件；允许正常完整对局模块替换。不需要任意 snapshot，也不要求有真正最优 oracle。
- **对照与替代法：** 先选最可能的两个因素做小型交叉比较，例如当前/稍早介入 × 原候选/增加一个实际可执行方案；或固定候选，比较两种会产生不同任务压力的响应式对手。人类参考若使用未来或隐藏信息，标为诊断提示，重新写成合法触发后才是可部署方案。
- **预期可观察后果：** 能看到失败是在下令前已难以挽回、候选没有有用动作，还是选择/执行不佳。记录不同对手实际如何反应，不能按仓库数量宣称行为多样。
- **否定条件：** 增加候选仍全被仲裁器过滤；较早触发才改变可到场兵力；“不同对手”在关键行为上完全一样。这些都否定只继续训练当前选择器的理由。若各组合确实无改善，保留该有限条件的阴性结论。
- **结论边界：** 有限候选的最好观察结果不是最优上界；从同一批中挑最高再报收益有选优偏差。负结果不能排除未试过的时机、方案、续局策略或合法信息表示。
- **失败后决定：** 扩充真正可执行的计划、调整更早的决策接口，或先修更上游瓶颈；若发现可复验且对整局有价值的选择差异，再比较规则、搜索、监督或 RL。若实验没有改变任何下一步决定，停止同类扩张，重新选问题。

## 对抗式“伪改进”测试向量

下表是**人为构造的分析输入与预期判定**，不是比赛记录或已运行断言。可直接用于审查实验设计；未来只需实现相应记录/适配器测试，不必先写一个替代引擎。`visible`、`mask`、`taskEpoch` 等是说明字段，不冒充原生 API schema。

| 向量 | 明确构造的输入差异 | 容易被宣布的“进步” | 应守住的判定 / 关联卡 |
| --- | --- | --- | --- |
| V01 掩码信使 | 两份输入 `visible/history` 相同；只改变裁判专用隐藏单位，生成的 `mask[attack_region]` 随之不同 | 模型没有读敌方字段，却学会预判伏兵 | 执行路径已泄漏；修 mask 来源，不能以模型输入白名单放行。E01 |
| V02 保守失明 | 一条按已声明协议应被保留的合法事件，因通用“视野离开就清空”规则从记忆删除 | 小模型需要更长训练才能理解局势 | 先否定表示完整性；事件是否该保留依锁定引擎与协议核验，不套别的 RTS。E01、E05 |
| V03 沉默高手 | 首次发出有效任务后禁止新令，单位仍按该任务行动；报告把之后成果标成持续决策贡献 | 学习控制器在每个 tick 都做出了好决策 | 只能归因初始任务与后续默认执行；不发新令不是零行为。E02 |
| V04 后到的旧命令 | 观察版本 `o1` 的任务代次为 `e1`，随后任务已变为 `e2`；`e1` 的计算结果最后返回并被发送 | 新模型平均推理更快，控制应更好 | 代次与前置条件比完成顺序重要；更快均值不抵消错序覆盖。E04 |
| V05 忘掉承诺 | 两份接手记录最后观察相同，一份包含已执行生产与预算承诺，另一份省略；候选重复分配该预算 | 新策略更积极投入生产 | 这是历史缺失的差异，不能当策略收益；须追踪实际执行。E05 |
| V06 把损失移出镜头 | 测试窗口内撤退部队存活，保护目标在窗口后失守；局部报告只保留部队血量 | 微操明显改善，战略问题以后再说 | 暂不成立的是任务层收益；延长相关后果记录，并让完整对局判断交换是否值得。E06 |
| V07 给模型记执行器的功 | 两版本在同一合法输入记录选择同一方案，新版本却减少重复命令；报告将后续改善归因于新模型 | 学习到了更好接战策略 | 先归因执行路径；只有选择器增量与交互有证据才扩大声明。E03、E07 |
| V08 胜者留下 | manifest 中自然完成、超时、bot 错误同时存在，报告只读取自然完成记录 | 候选胜率上升 | 启动局到报告必须闭合；删掉失败类型不产生竞争力证据。E08 |
| V09 复制的置信度 | 同一个来源/初始化批次的记录被复制并赋予新行 ID；汇总器将其全算独立样本 | 胜率差距终于有很窄的区间 | 行 ID 不创造独立性；检查分组、重跑原因与实际来源。E09 |
| V10 单动作全知标签 | 一条只执行 A 的记录附加 `B_better=true`，来源只是“后来赢了”或另一个模型预测 | 已获得足够反事实数据训练排序器 | B 的效果未被观测；预测可作标明来源的伪标签，不能作引擎真值。E07、E10 |
| V11 被安排的无能 | 所有候选都在主力已无法及时到场时介入；更早决策没有进入实验集合 | 已证明这个问题不值得学习 | 只证明本次时机/候选/续局条件没有发现改善；先做机会诊断。E10 |
| V12 多仓库同打法 | 对手名称和来源不同，关键任务中均执着追兵；候选靠引走敌军持续得利 | 已通过多样对手验收 | 若声明跨行为泛化，须覆盖会转攻目标的反应；若目标分布确实仅含追击型，就限制声明。E06、E10 |

本轮最有价值的产出是：排除一个会误导近期选择的解释，或发现一个真正值得优化的决策点。卡片数量、全部打勾、更多“失败但合规”的报告都不能替代这一判断。
