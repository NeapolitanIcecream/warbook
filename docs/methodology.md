# 研究方法与 AI 架构

状态：2026-09-15 的设计基线。来自本次 Codex 讨论及 [用户提供的 Pro 分析](references/gpt-6-pro-original.md)；没有引擎实测、训练或实战成绩。具体 API 事实以 [环境审计](environment-audit.md) 为准。

## 1. 目标与证据

开发一个在明确规则、信息、操作和计算条件下，能在正常完整对局中持续提高竞争力的 Chrono Divide AI。核心目标可以表达为目标对局分布上的结果：

`J(policy) = E[score(policy, match_conditions)]`

对局分布包括引擎/规则版本、地图、出生位、国家、对手家族与操作限制。胜、负、平局、超时和异常的处理需在评估前确定。平均成绩与常见打法上的脆弱性分别报告，不能只优化场景生成器容易产生的局面。

起步建议固定一个国家和少量陆战地图，保留正常经济、生产、侦察及完整终局。具体选项尚未确定。后续逐步扩展国家、地形和机制；受限阶段的成功不能替代最终覆盖目标。

三类成果需要不同证据：软件正确性由实际状态与动作效果支持；局部能力由有上下文的比较支持；整局实力由目标分布上的独立对局支持。训练奖励、预测准确率、伤害、存活和经济指标均不能自动替代整局结果。非传统打法可以有效，是否像人类不是最终标准。

此前失败闭环的工作假设是：方法、场景、评分和解释共享未经验证的假设，造成虚假进步。本仓库没有审阅旧代码，不能把这个解释当作已确诊根因。

## 2. 以最小完整闭环开始

先获得一场能完成、能观看、能追踪动作效果的正常对局。起步基线要能展开基地、维持基本经济与生产、放置建筑、组织部队、找到敌人、交战并结束比赛。策略可以粗糙，状态和执行必须可解释。

随后从真实失败中选出下一项工作。仅补充能解除当前实验阻碍的观测、测试或工具；不等快照、完整训练平台、所有机制测试全部完成后才打第一局。

已有 bot 可作工程和对战对照，需独立检查其版本兼容性、信息与操作条件、实际打法。单独战胜某个 bot 不代表通用实力，也不因使用外部对照而继承旧项目架构。

## 3. 环境与信息契约

策略路径为：

`引擎 → 合法观察 → 记忆/估计 → 计划 → 小队任务 → 单位控制/仲裁 → 动作效果 → 引擎`

保留三个明确的数据空间：

| 数据 | 允许用途 | 边界 |
| --- | --- | --- |
| 引擎真值 | 裁判、调试、明确隔离的训练辅助 | 不可间接泄漏给 actor |
| 合法观察 | 当前策略输入 | 依据所选比赛规则，不按 API 名称推测 |
| 历史与估计 | 敌情、意图、经济和军力推断 | 标记最后观测时间、置信度与假设 |

规则知识、静态地图知识、精确单位属性、起点信息和操作限制分别写入协议。不要凭惯例认定某字段合法或非法。按 Chrono Divide 实际 shroud、探测和伪装规则实现过滤，避免套用另一种 RTS 的持续视野模型。

检查间接通道：事件、对象 ID、数组顺序、动作 mask、全图统计、路径查询、运行时模拟等。隐藏世界改变而合法历史相同的情况下，actor 的输入与决策分布应相同；固定策略随机状态时应得到相同决策。训练 critic 如使用特权信息，应与部署 actor 的接口隔离。

部署先以外部控制器为工作默认值，并在实施时验证调度。若以后把代码集成进同步游戏逻辑，必须重新检查推理数值、随机性、时序与确定性条件。小模型训练完成不等于能直接部署；尤其不能假定把同步 bot 回调改为 async 后引擎会等待。

## 4. 可替换的控制结构

| 模块 | 初始实现 | 候选学习内容 |
| --- | --- | --- |
| 观测与记忆 | 合法数据、敌情时效、生产承诺 | 敌方计划或兵力分布估计 |
| 经济与战略 | 少量开局、预算、科技依赖、干扰恢复 | 计划选择、生产配置、扩张时机 |
| 战术任务 | 侦察、集结、守备、骚扰、交战、撤退 | 目标、部队分配、进退与增援判断 |
| 单位执行 | 命令确认、去重、目标失效、卡住恢复 | 集火、走位、技能时机 |

战略任务至少表达目标、所属单位、预算、优先级、持续条件、退出条件和紧急中断。统一仲裁同一单位的命令及同一笔资源的使用，避免模块争抢。适度承诺时间和切换滞后应通过实测调节，不能成为无法及时响应的硬性限制。

建筑的即时可放置性与长期布局价值不同。应检查是否堵住工厂出口、采矿路线或后续扩张空间；具体通路与扣费语义由引擎实验确认。战力估计要考虑何时能到场、能否接敌、阻塞和增援，不能只比较总造价。

分层帮助定位失败，但会限制策略空间。只把合法性与可靠执行做成必要约束；战术偏好应可替换。候选集合没有好方案时，先扩展方案和时机，不将所有问题归为选择模型不足。

一个玩家本可集中协调自己的单位。无需因 MARL 文献惯例而人为禁止合法信息共享；逐单位共享网络、小队策略或集中策略可按实际需求比较。

## 5. 数据来源与因果含义

优先采集正常完整对局，来源包括多个脚本/候选、历史版本和条件允许时的人类示范。混合采集典型事件、失败时刻和随机普通时刻，记录来源与抽样方式。学习者上线会改变遭遇分布，应持续从其新对局中补充数据。

replay 立即可用于事件审计和行为分析；可交互分支必须另行验证。复制单位、坐标和血量不能恢复完整世界：还需要相关冷却、弹道、队列、任务、资源、待执行指令、情报历史和控制器记忆。不同模型通过相同合法历史预热各自记忆，不能互拷不兼容的隐藏状态。

分叉后用会响应局势的对手；原录像后半段动作只代表原局势中的选择。若使用固定序列，明确报告为开环实验。缺少精确恢复时，可以进行正常开局的模块替换、随机分配及分层整局比较；相近局面不能声称精确反事实。

**只观测到已执行方案的结果，不能给未执行方案凭空生成效果标签。** 终局胜利是轨迹结果，不能直接证明其中某次动作造成胜利。候选比较来自经校验的分支实验、明确假设的模型或带不确定性的专家判断；后两者不是引擎反事实真值。每个标签记录方案、任务、时间窗口、续玩策略、合法信息和来源。

## 6. 按瓶颈选择方法

| 方法家族 | 适用条件 | 第一项判别实验 | 结果如何改变路线 |
| --- | --- | --- | --- |
| 参数化规则 | 机制清楚、变量少 | 同一评估下比较手调与简单参数搜索 | 能改善则保留；无效则检查状态、目标或执行 |
| 搜索/规划 | 候选有限、预测较可靠、延迟允许 | 同一候选集比较规则与预算受限搜索 | 模拟好而实战差则检查模型排序失真 |
| 监督/模仿 | 有合法输入对应的可靠标签 | 简单模型/候选排序与规则，再闭环部署 | 离线好、在线差则检查目标和状态分布 |
| 小模型 RL | 存在闭环决策空间、反馈可靠、吞吐足够 | 同一接口比较最好简单基线，重复训练与独立评估 | 只涨奖励或只一个幸运种子不成立 |
| 端到端 RL | 环境、数据、资源和评估已有基础 | 作为独立路线与混合系统公平比较 | 不默认由此承担项目首轮成败 |

参数优化可以从随机搜索等低成本方法开始。复杂优化器也需要和简单方案比较。搜索若依赖近似模型，应验证候选排序与真实引擎一致到足以支持当前决策；预测误差小并不必然意味着选出的方案好。运行时搜索不得使用 actor 不知道的真实敌情，应基于合法信息和合理的隐藏状态假设。

第一项学习模块可优先考虑可执行方案的结果预测或排序，但这是推荐路线，不是强制步骤。目标与时间窗口进入输入，输出可包含不确定性；仅拟合最终赢家不能自动解决动作选择。

如具备可靠分支，有限候选的离线选优可诊断是否存在选择改进空间。它受采样噪声、续玩策略和特权信息影响，是经验参考，不是全局最优上界。未观察到改善，也不能严格证明没有学习空间。应区分候选不足、时机错误、合法信息不足、选择器不足及模块交互。

模仿学习部署后，要检查自身错误导致的新状态。有可查询老师时可以借鉴 DAgger 进行针对性纠错；没有老师时不要把它当成现成能力。

## 7. RL、奖励与资源

首个 RL 实验应针对已确认影响整局的瓶颈；可能是进退，也可能是生产。环境、观察、动作效果、终局、非 RL 对照与固定评估需要足以支撑该实验，无需先把所有其他模块都做到最强。

优先尝试有语义的宏动作或小队计划，并正确处理可变持续时间。不同任务的奖励累计、折扣与终止条件必须对齐实际游戏时间。

伤害、存活、资源和闲置时间作为诊断或训练辅助分别报告，主动寻找奖励上涨却丢失战略目标的轨迹。势函数塑形可作为备选研究机制；采用时需核对理论条件、终止状态、折扣、变长动作以及 actor/critic 的信息边界，不能视作解决函数逼近或自博弈稳定性的保证。正式验收始终独立于训练奖励。

测量端到端有效决策吞吐，覆盖初始化、游戏推进、观察编码、推理、通信、记录、重置和评估，以及开局和大规模交战。区分引擎 tick/s、策略决策/s、完整局/s；记录延迟分布、并行扩展与故障率。

`总时间 ≈ 所有配置与独立训练所需决策数 / 实测总吞吐 + 评估 + 数据准备`

不同配置吞吐不同则分别估计。样本需求从小规模学习曲线获得；模型小不代表经验便宜，也不预先承诺硬件、训练时长或高手水平。

对手池保留历史版本、多种脚本与挑战者。只和最新自己对战可能遗忘或形成共同盲点。微操改动接回整局后必要时做宏观 A/B × 微操 A/B 的交叉替换，以判断模块交互和任务目标是否错配。

## 8. Codex 的研究循环

一次任务从观察到的具体失败开始，使用 [实验模板](../templates/experiment.md)：列出当前假设和竞争解释，规定能否定解释的结果，实施最小干预，检查正面、负面和含糊证据，决定保留、切换或下一项验证。

例：第一次主力接战失败，可能是经济不足、分批到场或命令干扰。分别检查接战前可到场兵力、到场时间线、指令与实际开火/移动；先改一个相关模块。若需两个模块共同变化，明确实验设计及交互，不把多项同时改动归功于单一机制。

每轮保留最少但充分的证据：运行标识、版本与配置、合法观察、任务与资源、候选和选择、发送指令、后续效果、结果与反例。记录事实和原因码即可，不要求生成冗长事后叙述。回放画面与结构化日志对齐时刻。

多 agent 分工可以让实现、竞争假设与复核并行；独立性来自不同证据和固定裁决条件，不能只靠模型互相认可。评测协议变动单独记录并重测基线，无需为每次合理修正新增审批程序。

Agent负责审查新失败类型、控制器分歧、模型不确定性和局部/整局冲突，并保留随机抽查。用户仅以用户/玩家身份反馈体验；Agent自行关联版本、录像和状态，转化为实验与修复任务。可用的人类示范或专家意见是补充来源，不把用户变成必需的实验设计者或常驻审阅员。经验证的机制错误转成检查，不将主观战术偏好硬编码为标准答案。早期真人对局帮助发现盲点，但不承担强胜率结论。

连续没有行为改善、没有排除假设、也没有解除实际阻碍时，停止同类局部调参，比较不同机制。负面结果若改变下一步决策，也是研究进展；文件数量、代码量与奖励曲线本身不是。

### 开发速度、结构与性能的平衡

该约定同样适用于分析方法。每项改进先写清已有问题和实用验收，使用旧记录或小规模真实实验检查；更多指标、图表或抽象本身不算进展。当前实现及保留决定见 [分析工具](analysis-tools.md)。

用户明确的战略偏好是：一切为又快又好地提供 RA2 AI 服务，避免沉迷基础设施细节及设计、代码和实验中的过度防御；同时不能只堆代码，需要定期检查重构与性能优化需求，确有需要时先改善再继续。这是持续开发约定，不是要求当前立即重写已有探针或建立新的管理工具。

对当前目标采用直接、足够清楚的实现，复用已有能力。只保留能影响当前行为、实验解释或交付判断的检查；不为假想未来需求预建抽象、回退层和穷尽测试。场景卡与实验模板按需使用，不能变成每次改动必须全部通过的清单。未知条件用最小判别实验推进，源码理解或当前局部证据已足够时，就进入下一项真实工作。

默认每完成 3 轮实质开发/实验迭代，或到达一个里程碑时，做一次简短结构与性能回顾；小提交不单独计轮次。反复打补丁、同一改动跨多个职责模块、控制权混乱、接口阻碍实验、故障难定位，以及执行/采样明显拖慢时，提前检查。回顾可以在当前任务内完成，不要求单独立项、报告或固定投入比例；没有具体需要就继续。

若发现重构或优化确实有助于当前可靠性、可维护性、迭代速度或有效采样吞吐，暂停受影响的新功能/实验工作，自主实施最小有效改进。结构问题可由具体修改成本和耦合证据支持，不必等待性能数据；性能优化则先对相关负载做简短测量，再在相同工作量、行为和决策预算下比较。降低决策频率、减少实验覆盖等若改变任务，应另记为行为/协议变化，不能包装为等价性能提升。

改善前明确要消除的问题及恢复主线的条件，完成后验证相关接口/行为与适当回归。性能改动报告相应吞吐、延迟或资源差异；纯结构改动不要求证明胜率显著提升。问题解除就恢复主线，不借此扩成全面重写；无关工作可以继续，无需再次请求用户确认。

## 9. 研究依据与借鉴边界

- [SMACv2](https://arxiv.org/abs/2212.07489)：旧基准的开环捷径提醒我们验证被测能力；程序化随机化不自动证明跨真实对局泛化。
- [PGS 在真实 StarCraft 的评估](https://ojs.aaai.org/index.php/AIIDE/article/view/12962)：近似模拟中的优势需要真实引擎检查。
- [DAgger](https://proceedings.mlr.press/v15/ross11a.html)：学习者诱发的状态分布应进入纠错，方法需要相应老师与反馈条件。
- [AlphaStar 官方总结](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)：借鉴模仿、多样策略和挑战者的组织，不据此承诺本项目的样本成本或实力。
- [PSRO](https://arxiv.org/abs/1711.00832)：训练伙伴过拟合与策略混合的依据，不构成这里已经求得均衡或 exploitability 的证明。
- [Statistical Precipice](https://arxiv.org/abs/2108.13264)：有限训练重复下应报告不确定性；统计方法不能补救无效场景。
- [奖励塑形原论文](https://people.eecs.berkeley.edu/~pabbeel/cs287-fa09/readings/NgHaradaRussell-shaping-ICML1999.pdf)：势函数变换有特定理论前提，工程适用条件仍需核查。
