# 0.1.15：侦察、持续作战与共同演进

本轮把 0.1.7–0.1.14 的玩家反馈和 Supalosa 源码研究落实到完整对局。原型、失败及后续修正保留在 [过程记录](iteration-015.md)，没有把它们拼成最终成绩。

## 行为变化

- **侦察有明确目标和完成条件。** 优先揭开敌基地周边；从真正未揭开的可达区域选点，避免固定网格漏掉黑幕小块，也不再反复访问已经揭开的地块。侦察犬身份持续保留，和护卫犬分开。搜索以主群位置为依据，车辆不再追逐步兵专用或不连通的位置。
- **任务持续，局部接战独立。** 行军途中不因一次全局估计变化而全军返家；短撤、等增援和清场后继续搜索分开处理。小部队仍检查支援，成规模军团可以建立前沿压力；遇到受阻接触时可以沿地图上的另一个入口分出装甲侧群。
- **让已有火力参与。** 攻守共用目标选择与射程判断；单位有射程内目标时先开火，共同目标在射程内才优先集火。GI 保持有利接战，按需要移动、部署、解除部署，并支援近基地碉堡。受损装甲可向友军后方短撤，保留有效的近距碾压。
- **经济和兵种有后续发展。** 建筑维修、可见收入建筑的工程师占领、更多矿场/矿车/产能、前方在采矿区驻守。扩张和额外护卫犬不会抢在首批装甲之前。受阻后的盟军路线可以发展雷达、实验室和少量光棱坦克；远程车辆保持在装甲后方，不执行坦克碾压动作。
- **压制路线继续独立演进。** 保留双路步兵压力，停止向完整防线持续补充无支援步兵；坦克形成攻击后再共同推进。出兵后补一座有步兵支援的家防碉堡。主线和压制分别冻结，不用历史控制替代挑战者开发。

地图采用锁定引擎的只读通行规则和独立 ngraph。步兵、车辆、桥上、桥下分别处理，开局之后只更新已探索区域；单位完整移动由原生 Move/AttackMove 完成。边界和运行检查见 [环境审计](environment-audit.md)。

## 验证与实用边界

- 类型检查、133 项机制测试。测试覆盖实际发现的部署、分兵、目标选择、生产、地图层、可达搜索和停滞诊断问题。
- 五份最终回放（四图主线及压力路线）共 1,570 份原单位快照、资金/败北和停止状态匹配；另两局主线同观察指令比较 7,742 次、零差异。机制测试不能代替整局，GUI 验证也不计作对战胜率。
- 简报保留实际移动、敌建筑受损、火力参与、最近新建筑接触。增援加入不会抹掉原有兵群的停滞证据。新建与迟发现、下令与执行、几何射程与真正开火分别说明。
- 剩余两场上限发生在交战损耗后的有限兵力相持，未按胜利处理。当前仍是地面作战研发版；伤员轮换和有限侧翼并不等于成熟的人类 T 优微操，完整 RPA 执行器及所有兵种/阵营也不在已验收能力之列。
