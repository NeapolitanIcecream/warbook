# 局部机动权限原型

2026-09-22。接敌信息对照正在以独立冻结源`884428b`运行；本原型另行开发，不混入该对照。旧败局12:00的合法记录显示目标附近1辆敌坦克、主力12格内7辆，进一步说明区分目标与接敌位置有实际价值；它不是替代动作获胜的反事实证明。

## 具体执行缺口

合成命令探针中，两辆坦克接到后方位置的`assemble`任务，仍向附近敌车发出Attack；同一局面使用`withdraw`则发出目的地Move。原有集结语义允许优先接战，不能把新增集结点当作已经得到受控机动。

原型复用现有Move执行路径：额外提供最多两项当前编组的局部机动，均不带新增兵量，不建立第二个模型。

- `local-regroup`：主力最大邻近组内的真实占用格，供远处成员靠拢。
- `local-return`：仍属于该主力的可见成员，在近60游戏秒中实际走过的格，距当前组中心4–10格；最多保留每成员8个位置。优先提供离当前可见威胁较远的一个历史格，无敌情时参考当前目的地。候选生成给出有限移动能力，不声称RL发明了这些地点。
- 所有位置来自本方合法观察，不取平均坐标落点、不查实时SDK寻路、不把未知敌军用于风险或掩码。只排除本方建筑占位等已知不可执行条件。历史占用不保证后来没有动态阻挡，仍需完整局检查。
- 局部任务使用既有withdraw执行语义，避免自动接战取消移动；KEEP保留目的地。记录保留局部目标类型，不能将它自动解释成退回基地。相同目的地不重复作为一个新动作，局部任务也不与补兵档组合。

## 比较方式

当前使用`operation-maneuver-v1`：217维global、50维候选、最多77项，同一个共享打分网络，共95,490参数。相比contact模型只新增两个候选输入列（256个actor参数），critic不变。`maneuverScope=base/local`显式控制菜单；两臂同步接入落点最近可见威胁距离和水平射程覆盖数量，新增权重/Adam矩置零，其余权重、矩和步数保留。

**扩菜单会在训练前改变完整动作分布，不能声称两臂初始策略相同。** 比较中必须保留新增菜单但尚未更新的模型，作为使用相同原语的固定选择器；再比较两臂各自PPO端点。由此区分新增可选动作的即时效果与进一步RL学习的效果。

复用`contact_cycle.py --experiment maneuver`：两路线各两臂两重复、3轮×192新局。信息对照未显示主线继续训练的稳定增益，主线从其未更新local迁移起点继续；压力从local47第三次更新继续，并保留其他强候选。两臂在各自路线共享起点及Adam，新增落点输入零迁移。

新的训练池将饱和的Supalosa替换为对方路线的固定起点：0.1.16主线、0.1.16压力、对方强窄权限、对方固定起点、对方两臂当前冻结模型，仍是6个对手。依据是上轮所有最终模型对Supalosa均32/32，而主线未更新起点对新适应对手仍比几个更新端点强；旧强者需要继续提供选择压力。最终7对手池再加回Supalosa，重新比较全部起点/端点/规则及未训练的新菜单参考，共预定8,192局（4,608采样、3,584最终比较）。这是新的开发池，不能与上一轮总胜率直接相减。
