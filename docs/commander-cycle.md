# 完整战略模型实施

2026-09-23，用户已授权继续实施。分支`codex/full-strategy`；稳定玩家仍0.1.16。目标是让一个模型负责当前支持内容内的生产、科技、采矿/侦察区域、建筑落点、维修/出售及多编组任务，并跑通真实整局训练和玩家出口。沿[设计重审](learning-redesign.md)，不再把两项装甲菜单扩展作为最终范围。固定战术作为首个可运行执行基线，短课程和可学习战术仍须继续落实。

## 已实现的接口

- 生产由显式程序执行：六类队列的产品/目标存量、暂停/恢复/取消及现金底线；模型选择建筑落点、维修开关、出售与基地车展开/收起。执行器不自动补电、换兵种或决定修理优先级，矿场附送矿车仍做机械记账。
- 16个持久任务槽与逐单位归属，允许分拆、合并、改派、局部撤回、侦察、采矿和占领。保留原生命令、明确Stop和主动部署有不同语义。未分配的新单位不会自动被Stop。
- 合法实体与记忆、独立地形图收缩得到的区域/连通边、产品与前置依赖图、当前生产承诺/任务共同作为输入。区域中心来自实际通行格；战略区域投影不是无损复制原老师选位。落点候选只检查已探索脚印与引擎合法性，旧位置推荐仅供教师使用。
- 网络为共享实体/区域/产品编码、稀疏邻域汇总、128维GRU和条件化计划解码。先选择生产计划，再条件化解码任务类型/区域、各单位归属、建筑操作和放置位置。一次策略的概率是所有实际选择因子的乘积，KEEP/掩码语义一致。当前数值探针模型316,840参数（含critic与该探针词表），尚未训练。
- 模型模式不创建旧战略教师；可显式选择正常开局的教师前缀。前缀期间模型只暖启动记忆，之后在同一引擎实例接管；前缀动作不能作为PPO策略动作使用。

## 首轮真实运行与修复

显式生产教师的第一局正常胜Supalosa。接入统一任务图后，发现两个实际执行问题：新矿车被未分配任务的Stop打断；语义Goal中的`kind`随坐标展开后覆盖了原生Intent的`kind`，造成记录“提交”但没有真正执行移动。已分别区分保留原生/停止/采矿自动行为，并在任务出口剥离Goal元数据、在编译及桥接处拒绝未知命令类型。针对性回归覆盖两者，不把这些失败当作学习方法失败。

修正后的主线14,980 tick、压力10,884 tick均正常击败Supalosa；只是接口运行证据，不是实力矩阵或新模型成绩。此前失败/上限记录保留在`runs/commander-*`，不进入正式示范数据。原逻辑任务位置被投影到合法区域/实体目标，完整比较必须记录其代价。

PyTorch与TF.js CPU用四个实际记录状态及包含非零隐状态的数值探针比较14,510个标量，最大误差2.23e-7。目标类型名一列从记录中的公开名称重建，仅用于数值探针，不是正式训练数据或真实连续策略轨迹。检查点在忽略目录`work/commander/`，CPU服务器草稿在`jobs/commander-dev`；随机权重不是候选成品。

## 当前继续事项

补充实测：随机权重在正常游戏的3,000 tick教师前缀后接管，真实执行了自己的建筑/部队决策，随后自然败北，0执行错误；这不是训练成绩。原生程序动作探针依次确认暂停、恢复、取消/退款、完成放置和出售：阶段0→7、最终tick633，全部符合预期；它是机制测试，不计整局胜利。

初次实际模型接管的推理过慢。定位到TF.js CPU的`unsortedSegmentSum`，改用已有`tf.sparse.sparseSegmentMean`，保留没有入边的末尾节点。相同四个记录输入、相同随机权重、每项预热3/测12次，Node中位约558–570ms降至6.8–7.5ms，测得P95为7.2–9.1ms；数值复验最大误差1.94e-7。这仅是这四个状态的推理比较，未包含完整浏览器游戏负载或更大部队上限。原始测量在`work/commander/timing-{before,after}.json`。

冻结可运行源并采集两路线示范，完成序列BC/PPO及真实对照；核对模型所有控制域的实际命令、数值一致性与MacBook完整链路成本。接着落实正常前缀课程和短装甲场景，并准备脱离笔记本的后续训练。原生动作探针已经通过；新架构尚未发布，不按管线能运行声明策略已经变强。

## 首次训练、零胜与具体修正

第一批采集暴露了旧教师“占领目标失效时送工程师回家”的表示分支错误，已在`5f36756`明确译为withdraw并重采，失败批次不混入正式数据。修正后四图、规则主线/压力/Supalosa/旧强MC83，各路线128局：主线61W59L8U、压力62W59L7U，0E。

`9dc89a4`实现序列BC/PPO、CPU DDP与玩家/冻结包加载。实测多线程小矩阵反而慢，改为每进程单线程；两进程更新与导出检查通过，中央与分片梯度误差1.12e-8。四份正式BC各用103个完整训练局、25个留出局，8进程/模型、6 epochs，在约10分钟内完成；更新后Torch/TF.js误差小于8e-7。

四份BC整局初评均0/32胜，0执行错误。检查实际首步显示全部选择KEEP，没有展开MCV，整局只有基地车。损失下降不能替代关键动作的学习。固定main47，在一个实际开局状态上做80次额外拟合，部署概率0.119→0.367，KEEP0.374→0.179，贪心动作变成部署；这是有限拟合证据，不是新对局成绩，也不能证明所有战略的容量充足。下一次BC采用连续整局记忆，并提高部署/放置/新生产与分配事件的监督权重，保持推理期由模型选择，不加入强制开局规则。

用户授权的Pro第六轮审查固定`9dc89a4`，本地复核并修正：

- 完整战略75-tick放置时钟被旧30-tick工事节流永久错过。统一完整战略候选扫描时钟，回归覆盖Ready偏移72/75/78；旧规则路径保留原节流。
- Harvest→Stop→同槽同矿点的缓存未失效。统一hold交接，清除离开采矿后的目标/旧伤害与逃逸缓存。真实引擎已观察Gather(2400)→Stop(2403)→Gather(2433)，之后载矿增加，tick2617完成。
- BC窗口从零记忆加短burn-in，与部署的持续记忆不同。改为按episode连续推进，相邻块携带h并detach梯度；留出验证同样连续。PPO保留行为hidden与burn-in路径。
- DDP短分片的取模补齐重复了真实窗口。改为零loss空分片同步；每个真实窗口每epoch一次。3帧/8帧梯度比较最大误差2.99e-8，空分片梯度为0，调度回归覆盖2/5窗口。

这些修正分别解决已观测或代码复现的问题，尚不证明BC已经有实战能力。冻结训练源未热改；新结果需重新完整评测。

## 短战斗入口

使用官方原生初始部队和真实Move准备，不调用spawn/teleport/restore。`unitCount=20`实测仅提供各5辆基础坦克，首次选择4辆/方，在独立地形图中选隔离的开放区域；其余单位不参与。当前actor只读本方单位和当前可见敌军，敌方冷却不输入。环境裁判另监控非参战者损伤、开火与距离，污染则拒收。

两份4v4原生AttackMove对集火的完整局部战斗正常结束，集火方胜；其中准备411 tick、战斗524 tick，总墙钟约0.54秒。它是有成功见证的局部任务，不是正式1v1胜利，也未训练新的微操模型。任务边界与准备成本显式记录，短场景成果仍须迁移回整局。

## 从教师轨迹转向实际访问状态

BC2第3 epoch四份模型都能在开局记录中选择部署，但随后的16场纯模型完整局仍全部败北。实际记录显示展开后持续KEEP，未下第一座电厂订单。第6 epoch在真实教师tick75状态上电厂概率约0.24–0.36，仍低于KEEP；不能以总loss下降或学会一个动作验收。

加入显式DAgger采集选项：在学习者访问的实际局面查询同路线教师，并按可记录beta选择教师或模型实际执行；保留`action`与`teacherAction`两份含义。BC可学习专家建议，PPO只使用实际执行的policy动作和对应logp。运行期不设置此选项时完全不构造教师。针对性检查确认beta=0不会把教师的展开动作偷偷执行，beta=1真实标teacher且不冒充policy概率；目的是补齐停滞/失误状态中的恢复监督，是否改善整局仍待新结果。

R3教师采集128局全部无执行错误，主线26W36L2U、压力29W35L；其中真实胜局记录tick4050包含碉堡放置，放置时钟修复已越过mock范围。初次同池规则对照32局分别21胜/16胜、显式教师16/15胜，接口投影/低频控制仍可能有代价，不能说教师等价于原策略。

DAgger小检查8局无错误，带25%教师介入为主线2/4、压力3/4；随后128局采集无错误，分别15W46L3U与13W50L1U。它们是混合控制的数据质量证据。BC3从同一路线BC2起点，分别继续常规教师数据、或加入新访问状态的专家标签；每臂8进程，最多2400更新，保持两路线。第2 epoch纯模型16局仍全部败北，但从无建造推进到真实下电厂/矿场订单（部分峰值6个己方对象），仍未形成可接受的基本能力。需要继续训练和验收，不晋升默认。

## 可学习装甲技能入口

独立共享单位/目标网络24,609参数，输入合法局部实体、相对坐标、任务目标与己方武器状态；敌方冷却明确不输入。输出每辆坦克的原生Keep/Stop、局部Move/AttackMove落点、可见敌方目标。由模型选择目标和移动，执行器只做归属/可见性和重复命令处理。该初始技能课程仍限地面装甲互战，不能声称已经学会步兵部署或全部战术。

8个真实2–5坦克状态的Torch/TF.js共1016数值对比最大误差9.79e-7，反向梯度有限；随机权重实际进入4v4、执行采样命令并正常任务败北。2/3/5车及mp06/mp08/mp03的原生准备和局部消灭也已运行，相关实例均释放。三图检查不证明每个普通随机出生都能准备成功；采集器保留准备失败并拒绝把它们混成正常任务。后续先监督初始化和局部PPO，再接回整局检验迁移。192项Node检查、类型检查通过。

实际384场教师局部任务已全部完成，0E，269次A胜/115次B胜，墙钟22.33秒（64并行，含真实移动准备）。两份独立BC各20epochs、约203秒；按完整episode留出的命令正确率均约92.84%。同批192局部任务：BC47为34A14B、BC83为33A14B1U、集火教师31A17B、原生AttackMove为13A35B（各48）。这支持已学到可用的基础集火，不足以声称超越教师，未替代整局评测。

已接入整局可选装甲技能：基本坦克处于advance/defend并接触可见地面目标时，每15tick由独立网络选择原生命令；其余角色与行军保留原执行方式。整局真实命令另记`armor_decision`，模型哈希记录在manifest。随机权重整局达到54,000tick上限；训练后47模型配合规则战略在短图19,332tick正常胜Supalosa，0执行错误；这是迁移入口运行证据，尚非组件增益。局部任务RL将保留两个独立起点和固定对手池，正常整局继续单独比较。
