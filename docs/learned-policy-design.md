# 第一个学习实验：新装甲波次的承诺

2026-09-20。经用户指定的 GPT 6 Pro 两轮商议和本地源码/API/推理探针复核形成。本文件是待实施设计；玩家基线仍为0.1.16，没有开始策略训练。两轮原文、简报、会话状态和探针保存在忽略目录 `work/consult-pro/`；不将私人咨询记录上传。前期约定见 [学习边界](learning-boundary.md)。

## 1. 结论与范围

已具备开始一个受控学习实验的基础：完整游戏、可靠原生命令、合法观察、两条演进路线、冻结对手和可核对回放。无需先补完所有兵种/残局或建立通用训练平台。

长期保留战略与任务条件战术两个可学习接口；输入优先合法结构化状态及历史，输出最终落实为原生命令。是否有两个网络、共享编码器或联合训练由后续证据决定。首轮不同时替换两层，也不从画面/鼠标端到端起步。

**首个模型只决定新一波装甲何时出击、去哪里、投入多少。** 生产、侦察、步兵、矿车保护、既有矿区守备和局部战术继续采用冻结规则。装甲沿现有 `combatArmor` 口径包含基础坦克和SREF，保留混编、侧翼、增援与恢复的已有执行能力。

第一轮Pro曾建议新建主群/守矿两个角色。复核发现这会重写已有分群并影响生产，因此第二轮共同收窄为新波次决策。首轮不学习取消固定守矿任务，也不宣称已实现完整学习型战略；可支配预备队的0/全部投入不等于全军0/全部留守。

| 层次 | 输入 | 输出/控制权 |
| --- | --- | --- |
| 首个学习模块（战略中的新波次决策） | 合法实体与地图事实、历史、实际任务、未经风险筛选的目标/投入候选 | KEEP或一次新波次的目标、起始存量投入 |
| 既有战略状态机 | 实际观察与已提交的新波次 | 真正的assault/joining/withdrawing/flank状态、其余任务及生产计划 |
| 固定战术与生产执行 | 任务、授权成员、局部战场与反馈 | 原生单位/生产意图，接战与进展反馈 |
| bridge | 当前合法意图与引用 | 唯一命令提交与效果核验 |

假设：相同执行能力下，状态条件的新波次选择优于原规则及同接口的简单调参。若主要可避免损失来自经济/科技或正确任务下的局部战术，则改变下一学习目标；不能把所有败局都归给这个模块。资金耗尽且装甲全损的残局不作为本实验能直接解决的问题。

## 2. 有限动作与模型概率

每75 tick（约5游戏秒）检查一次；现有每3 tick的战术和执行循环保持。75是待测默认值。已有波次占用槽位时保持其任务，首轮不学习途中改派或全军撤退。

条件策略有三个头：

1. `KEEP / LAUNCH`，2项。
2. LAUNCH时选择最多8个目标区域之一。
3. 给定目标后，从 `1、ceil(N/3)、ceil(2N/3)、N` 中选投入数量，去重、padding并掩码；N是该目标当前可支配的装甲数量。

完整动作最多 **1 + 8 × 4 = 33** 种。KEEP是投入0、不修订既有任务；选N是投入该候选池全部兵力。无新波次槽位或无有效目标时只有KEEP，概率1，不计算actor损失。critic可使用合法状态。

每个数量候选预先物化为实际成员、兵种组成和数量。按冻结的机械规则保持兵种比例并选择成员，不让模型输出“六辆”而实际提交另一组兵。目标、组成、相对位置都是输入事实；成员引用只用于解析动作。

目标由当前合法接触、合法记忆及搜索点生成，不经过旧的兵力/风险评价。按粗区域、桥层及通行组件合并，采用有效实际位置；当前有效目标优先保留。超出8个时，以确定性的最远点覆盖采样保持空间分散，坐标处理平局。记录合并和省略映射：这种压缩会遗漏区域内细目标或第九个方向，不宣称无损。

硬掩码仅负责实际任务归属、引用、动作/桥层支持、已知不可达等机械条件。未知通路不冒充不可达；兵少、受损、分散、敌强或基地受压均不能伪装为非法动作。`localRef`、原生ID、对手策略名、run ID不作模型特征。

采样日志记录特征、候选槽位/成员/掩码、所选分支和实际TS策略的旧log概率。KEEP只计启动头；LAUNCH计三个条件log概率之和。PPO使用完整动作的统一概率比，不分别clip三个头；更新时用采样时保存的同一候选快照与前缀，不重新生成或采样候选。

例：固定守矿/救援之外有8辆可支配装甲，模型选择某炼矿厂区域和投入6辆；剩余2辆仍作本地预备，不会被同tick自动增援立刻补入。之后新造坦克可按冻结增援规则加入，所以模型控制的是本波**起始存量承诺**，而非最终总人数。

## 3. 输入表示

沿现有合法观察和记忆建立纯TS事实视图，不额外建一份与旧状态竞争的全局世界模型。训练端读取TS编码结果，避免Python和浏览器各实现一套特征。

- 己方实体：类型、位置/桥层、HP、公开能力、自己的攻击/部署/载矿状态、当前任务、到目标距离与受损历史。
- 敌方：当前合法接触与带时间的历史值，明确known mask、当前是否观察到、最后观察时间；未知不等于零。己方短暂不可用也不等于被摧毁。
- 地图：已有独立车辆/步兵图、通路/桥层、探索覆盖、已知动态资源与障碍。可从8×8格的区域事实起步，不能把桥层或不连通组件合并。禁止使用live SDK findPath/getReachabilityMap。
- 全局：己方经济、电力、生产、实验窗口剩余时间；不使用对手私有经济。
- 历史与任务：真实承诺/成员/年龄、到达、推进、接战、受损与支援请求。初始可用最近4个战略决策摘要加持久合法记忆，暂不需要RNN。

实体编码采用小MLP和置换不变的集合/区域汇总，并保留目标相对几何；不能只向模型输入手写优势分或“安全”布尔值。不得静默截断实体；必要聚合保留数量、类型与健康等信息。四个已有样本的最大对象数量不作为全环境上限。

## 4. 最小代码切分与真正控制权

复用Bastion现有的真实跨tick状态，先抽取选择接口，再接学习分支：

```ts
type LaunchDecision =
  | { kind: "keep" }
  | { kind: "launch"; targetSlot: number; amountSlot: number };

buildLaunchSnapshot(observation, actualState): LaunchSnapshot;
chooseLaunch(snapshot): LaunchDecision;
commitLaunch(snapshot, decision): CommitReceipt;
```

快照含tick/epoch、语义目标键、坐标/桥层、实际候选成员与合法性。执行顺序：更新现有真实任务 → 构造候选 → 选择并原子提交 → 根据提交后的真实状态生成其他任务和生产。不得先运行一套未执行的旧战略，再在输出末尾覆盖任务。

学习分支绕过旧 `Operations.consider` 的风险淘汰及最终单选，也绕过 `protectNow`、`nextLaunchTick`、搜索出击的固定数量条件，以及formed/集结距离门槛。这些事实可以成为输入。既有守矿、救援、撤退和作战任务的成员归属属于首轮固定作用范围，不由模型抢夺。出厂准备与命令实际可用性单独说明，不能仅凭位于工厂矩形就宣称非法。

保留旧Operation的兼容语义；可在选定后计算估计供原生产/侧翼使用，但不能再否决选择。来源单独标记，避免改一个reason字符串就意外改变光棱发展逻辑。

### 三处经源码核实的冲突

| 冲突 | 首轮必须明确的语义 |
| --- | --- |
| 启动后立即计算nextBatch，可能把未选预备队全补进去 | 保存`heldForWave = 本次候选存量 − 已投入成员`；本波结束前，自动增援排除这些存量。它们仍能守本地；之后新造/恢复兵力按冻结逻辑处理。 |
| `Operations.target`在active.ref无法解析时选择最近已知目标 | 将内部目标身份/位置与“当前可攻击实体引用”分开；承诺目标有效时保持，转换要记录核实清空、失效或续战原因。 |
| 原救援请求取决于responding且assault非空，出击本身可能触发回抽 | 记录发起时的防守证据；不能仅因成员进入assault就用同一证据抽回。新资产损伤或新威胁进入保护范围后，固定救援可接管并记录原因；不是纯合法性检查。 |

成员修订、目标修订与operation开始时间分开；加入增援不能重置已出发成员的任务年龄或集结等待。任务结束也不等于发送Stop。

`LegacyLaunchProvider`保留0.1.16原门槛、原成员和候选，且不受33动作离散化限制。首先对纯抽取做相同观察下的任务/生产/指令比较；数量离散化和上述三项契约改变单独验证，不混称无行为变化的重构。没有必要新建通用MissionLedger框架。

Legacy等价检查与模仿老师不同：前者不限制动作，只检查抽取；后者必须真正使用33动作接口，选择其中合法方案并完整执行。记录其相对旧策略的目标/数量差异和候选遗漏，不能把接口外的旧动作强行当作精确标签。这也提供动作空间损失的独立对照。

## 5. 模型、训练与试玩出口

比较同一动作接口下的：原兼容规则、便宜参数搜索/线性策略、规则模仿初始化的小网络、模仿后在线PPO。简单方案取得同样收益就保留简单方案，不以采用RL为交付标准。

首个小网络可从64宽实体编码、128维状态以及三个条件头起步；第一轮Pro给出的5万—20万参数是工程预算建议，按实际结构重算，不预先固定。critic只读actor可用的合法信息。Python/PyTorch训练，先测CPU再决定是否用MPS；本机默认Python 3.9.6尚无PyTorch，需要项目隔离运行时，不修改系统Python。

Node采样整局使用冻结checkpoint和与浏览器相同的TS编码/推理；批次结束后Python更新导出。避免每个决策跨进程请求Python。可复用CleanRL的简明PPO实现模式，需适配完整局采样、条件概率及固定窗口目标，不先引入通用Gym/分布式平台。

同步推理首选候选为TF.js core + CPU backend；开局前完成异步加载、backend准备和预热，decide保留同步。实际GameFactory.create也是同步的，不能直接把它改成async并假定客户端会等待；应在已有异步大厅准备等入口完成预加载，再允许开局。模型加载失败必须在开局前显式选定基线。

ONNX Runtime JS的run返回Promise，现阶段不直接接入同步回调。WASM或异步worker只有在完整决策链耗时不达标时再比较。权重、编码schema、运行库与代码一起冻结；训练/TS的掩码概率和动作选择要做数值与实际行为核对。

## 6. 数据、回报和对照

历史150-tick观察是诊断数据，不直接当作完整离线RL训练集。新数据在每个实际战略决策点记录特征、候选、掩码、行为概率、任务提交/接管、效果和完整局结果。保留胜负及未决，不把胜局每个动作标成正确。

第一轮明确优化“54000 tick内正式获胜的概率”：W训练效用1；L与窗口内未决U效用0，仍分别保留W/L/U/E标签，U不改名为失败或平局。输入包含剩余窗口时间。这与当前W/总启动数报告相容，但属于明确的有限窗口实验目标；不限时玩家对局及60分钟后的行为另验。

自然终止、采集异常截断、目标窗口结束要分字段。若将来优化最终获胜而不是窗口内获胜，外部截断的bootstrap逻辑需改变，不能沿用终局零值。首轮不加伤害、走路、发现目标、守矿时长等任意稠密奖励。

PPO可先使用完整局回报（gamma=1、lambda=1），按一批完整局收集新鲜轨迹，再更新少量轮次；clip/学习率/KL等采用明确记录的保守默认值。先验证梯度、行为概率和策略更新，再优化这些超参。大量强制KEEP不提供actor决策信息，应单独统计有效选择数。

| 对照 | 用途 |
| --- | --- |
| R0：原0.1.16整包 | 产品能力参照 |
| R1：33动作接口中的规则老师 | 分离动作抽象与学习收益；此前另有不限33动作的Legacy抽取检查 |
| R2：同候选/执行器的简单调参或线性策略 | 检查复杂模型是否有额外价值 |
| L0：模仿模型 | 验证可用起点，包含KEEP和真正修改任务 |
| L1：模仿＋在线学习 | 检验交互学习的增益和重复性 |

生产冻结代码/规则，不冻结每局购买时间表。所有比较保留完整局独立性；同局时间片、重放派生与双方数据同组，归一化只用训练数据。现有四图都是开发来源；新增验证/测试图需先锁定且处于支持范围，缺少时只声明开发池结果。

主线和pressure继续共同演化；采样块内对手池冻结，块间新增挑战者有独立版本。固定Supalosa/历史版本只作控制。记录真实出生位置，不声称配对seed。

## 7. 最小实施顺序与预算决定

1. 抽取LegacyLaunchProvider，保持真实状态唯一归属；用已有相同观察比较确认纯重构。
2. 新候选/commit接入，用具体反例验证：不利风险下合法发起仍可提交、KEEP不重置、部分投入不自动补满、目标不漂移、没有同证据立即回抽、SREF/侧翼和生产读取真实状态。
3. 新增真正决策点记录，测有效选择次数和完整管线成本；完整局检查回放与玩家操作。先做这些能改变决定的小检查，不预设48局接入门槛。
4. 同接口跑简单调参和老师采样；验证模仿不只学会KEEP。再做小规模在线试运行，按完整局反馈决定是否扩大、换学习目标或保留简单方案。
5. 候选有信号后才做多次独立训练和锁定评估，最后冻结可玩包。训练随机数可控制不等于环境seed可控制。

Pro给出的可扩展参考预算：老师128局、简单搜索192起步至最多1024、在线256局试运行后有信号再到每次1024局/三次训练，另计开发验证和最终比较。**这些不是本轮已启动任务，也不是必须花完的额度。** 下一阶段先测新采样成本再确定实际批次；不给复杂学习远大于简单对照的免费采样/调参预算。

完整管线分别测1/2/4 worker的真实经过时间、尝试/完成/异常、峰值内存和日志，不能把旧runner的7.686秒中位换算成承诺的训练时长。微型推理探针也不能代替这项测量。

不采用固定“+5个百分点”作为新增验收门槛。学习是否值得保留，要看相对最强简单对照的实际收益、独立重复、对手/地图切片、置信范围及可靠性代价；沿用项目既有评估纪律。若R1因动作抽象而变弱，先恢复能力；若学习只是打赢弱历史、反复被仲裁覆盖或收益只出现在单个训练重复，不扩大结论。
