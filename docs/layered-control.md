# 0.1.6：战略、战术与生产控制落地

2026-09-16。用户同意按 [分层设计](strategy-tactics-boundary.md) 实施。本轮先保持 0.1.5 行为，完成可替换的控制器、任务归属与效果反馈，再独立试验一个战术变体。没有引入新的模型、异步战略或 RPA 操作器。

## 实现边界

| 模块 | 当前职责 |
| --- | --- |
| `control/strategy.ts` / OpeningStrategy | 开局承诺、目标区域、全军任务及生产目标；声明需要检查哪类兵力的就绪情况，不生成逐单位命令 |
| `control/tactics.ts` / LocalCombat | 根据任务选择局部目标、碾压及行军命令；接敌/碾压距离和命令节奏由战术层维护；按战略声明报告可用兵力与出厂事实 |
| `control/production.ts` / QueueProduction | 落实有序建造目标、车辆/步兵目标和现有资金门槛；保留原有部署、生产与放置顺序 |
| `control/coordinator.ts` | 组合可替换控制器，管理任务修订和单位归属；拒绝任务冲突、战术越权生产、过期或未经当前决策登记的命令 |
| `bridge.ts` / `effects.ts` | 唯一 API 观察/提交入口，记录命令来源并将合法效果证据反馈给所属任务；移动只确认位置变化，不冒充到达 |
| `legacy-policy.ts` | 保留本仓库未迁移的历史 mode 及原实现；当前主线通过 `policy.ts` 转入新控制器 |

第一阶段只有一个主力任务和一个生产任务，保持同步 3 tick 调度。完整多小队分配、全局资金预留账本及撤退/骚扰等新任务类型尚未扩展；当前经济目标也没有夹带修复第五辆矿车的改动。这些能力按实际需求分别验证。

任务 ID 在本局控制器内有效；修订在目标、阶段、约束或成员真正变化时更新，观察数组重排不会重置任务。当前同步执行只接受最新决策产生的命令；将来慢速推理和 RPA 需要单独的有效期协议。

## 人类经验的修改位置

- “何时出发、是否回防、优先补兵还是扩矿”：战略目标与阶段条件。
- “怎样接敌、是否追击、碾压距离和微操节奏”：战术控制器。
- “不要漏算在建矿场附带的矿车”：生产记账与计划落实，作为后续独立改动。
- “点了却没有执行”：观察/执行桥及效果核验。

控制器可由构造参数单独替换。机制测试实际替换战术后，战略计划和生产指令保持相同；越权控制 MCV、夹带购买、使用旧任务结果或旧命令对象都会被拒绝。35 项测试及类型检查通过。

## 行为保持验证

runner 新增 `--shadow-release`：两份控制器在同一份合法观察上各自决策，记忆独立；影子不初始化引擎、不观察引擎、不提交动作。第一处语义意图差异会保存观察与两边输出并停止，不只比较稀疏的 150 tick 日志。

| --- | --- |
| 首局影子 + 四图矩阵 + 槽位补查 | 29 次启动，148,047 次逐步比较，0 差异；28 局正常结束，1 局达到 tick 上限 |

累计 45 条真实轨迹、222,445 次比较均未发现指令差异；其中最终包证据单独列出。影子只证明这些覆盖轨迹上的一致性，不证明所有可能局面等价，也不提供棋力提升证据。新实现实际控制了多场完整游戏，两种创建槽位均有检查。

上限局是 `layered-shadow-matrix/mp29u2.map/supalosa/0-published`：由原版 0.1.5 控制，54000 tick 时仍 Started、无引擎错误，双方未败北；己方没有矿车、资金 225，低于现有新队列启动门槛。影子 18,000 次输出均与旧版相同。这是保留下来的既有僵局，不算平局、胜局或本轮已修复的问题。

最终同观察测量中，原版决策平均约 7.03 微秒，新版约 11.58 微秒。该项仅计决策调用，不含观察、克隆、提交和日志；最终版的计划/报告日志已移至提交阶段。绝对成本目前未阻碍采样；本轮不宣称性能提升。早期批次曾把含报告日志的 decide 计时标作排除日志，不能将其误作纯算法测量；原始记录保留，正式比较采用最终批次口径。

## 首个独立战术实验

[grouped-advance-screen.json](../experiments/grouped-advance-screen.json) 比较默认 LocalCombat 与 GroupedAdvance。战略、生产、契约、观察及执行源码 hash 完全相同；只改战术和默认接线。原生群体命令仅合并进攻行军期间、同目标、同型号的坦克，步兵和交战指令分别保留。

- 两图 × counter / Supalosa × 每格两次 × 两个被评估版本，共 16 次，全部正常结束；双方各 6/8 胜。
- 实际出现多单位行军命令，说明替换已生效；不能因此认定队形或棋力改善。
- 四个选定回放的原快照与终局核对通过。短图 `counter/0-individual` 与 `0-grouped` 的四车首次冷却重启信号同为 6213、6252、6312、6606，首车损失同为 6328。第四车晚到问题仍存在。
- 城镇样本的起点不同，不能把其射击时序差异当成精确反事实。完整局没有新增胜场信号。

决定：0.1.6 继续采用 LocalCombat，GroupedAdvance 留作明确标记的研究类和冻结版本。减少单次批量操作与持续协调整队行军是不同问题；后续需要针对实际落后单位与接敌时机，而不是仅扩大同一帧的命令批次。
