# 下一研究周期：先检验完整战略PPO的学习深度与能力保持

2026-09-28，经用户指定的consult-pro两轮讨论，并核对仓库、历史训练记录及原始论文形成。**本文件是研究计划，尚未实现或启动训练。** 服务器上一窗口已于28日08:00结束；下面的墙钟计划从获得可用实验窗口、完成必要接入后计算。

## 研究决定及其依据

保留完整战略权限、当前约32万参数模型和原生有限批量执行器。**先让现有完整战略PPO得到更充分且可辨别的优化，策略空间搜索作为条件触发的备选。** 暂不新建层次技能系统、世界模型、快照平台，也不重启短装甲迁移。

第一轮Pro倾向以策略空间搜索为主。追加历史优化量核对后，它修正了优先级：旧有正向收益的主线MC每轮中位约882/864次Adam，24轮总计21,096/20,769次；有效actor帧使用中位173,526/169,272。新完整战略每轮8次Adam、约4,000有效帧，各线总48–64步。旧数字由冻结`f6d6d6e`循环与已审计records/epochCount复算，不是新训练。

**这些单位和学习问题不同，不能按步数倍数归因，更不能照搬882步。** 新模型有序列、多头联合动作、不同温度及梯度结构；64步与accum8的负/混合结果仍有效。新证据支持先检验合理的学习深度，不支持“多更新必然更好”，也不足以优先推翻现有学习器。

当前目标是：受实际压力后，完整战略模型能把经济恢复、持续生产和后续有效作战接起来，并让这种改进经新批次复验后仍存在。合理撤矿、转移、继续防守等均允许，不用固定动作答案验收。

- 按同一协议复测E0/B0。只有E0在独立创建批次反复丢失B0已有的基础能力，才做一次有界恢复与共同再校准；不因少赢几局就重开迁移工程，也不单独给某一方法臂加温。
- 旧强MC继续作为对手与能力参照；当前CommanderTeacher没有直接使用它。第一周期不把其教师接入、观察兼容和目标投影当作免费前提。

### 初始化的本地执行取舍

Pro第二轮建议统一冷启动Adam，避免重参数化状态混入。现有E0已做过更具体的处理：同名数量/现金末层状态重置，其他59项状态与父模型一致，B0/E0配套Adam逐字节相同且已核验。

因此**默认保留预先指定E0的配套Adam，P−/P＋从完全相同状态分叉**，避免再引入一次全量冷启动变量。若恢复阶段改变了初始化或决定采用冷启动，必须共同变更并重新定义第8步参照，不能称为旧配方的精确重放。这是Codex对执行细节的取舍，不把它写成Pro原建议。

## 2. 同一批数据比较“用得更充分”与“增加保持目标”

首个训练块从相同C0、相同Adam、相同随机轨迹和窗口顺序分叉：

| 分支 | 目标 | 保存端点 |
|---|---|---|
| P− | 原PPO目标 | 第8步，以及约25%/50%/100%有效帧覆盖 |
| P＋ | 相同PPO加行为保持项 | 相同覆盖端点；另保留第8步作诊断 |

第8步是有限曲线上的参照，不另开一条长期8步方法。按不同覆盖量比较P−，检验优化深度；在相同覆盖量比较P−/P＋，检验保持项。后续与S的比较是方法包比较，不单独归因给一个组件。

保持global batch32窗口、sequence16、accum1和原路线学习率作为初始设置。端点按累计有效actor帧定义，排除burn-in/padding，同时记录唯一窗口覆盖、重复使用与Adam数。若有3200个长度接近的窗口，一遍约100步只是算例，不能写成固定预算。

第一批最多一遍。25%已造成可重复的基本行为破坏，就不机械推进满遍历；校准最多允许一次预先记录的学习率缩小，从同一起点复跑。不以平均KL单独放行，也不因一批64局相差几胜就断言训练已经失效。

较深更新的诊断应以当前权重沿完整实际world历史重算hidden，检查旧记录状态/短burn-in是否影响结论。若构成实质问题，两臂共同修正历史处理后重比；不能让一臂换了RNN条件还将差异归给损失函数。

## 3. 行为保持项的具体含义

它是对已知策略的软约束，**不是能力保留证明，也不是运行期规则救援**。λ=0同深度对照必须保留；无收益就不用它。

冻结共同C0为参考策略π₀。在一条实际world历史H上，参考采样完整合法动作链A⁰；学生和参考沿相同的教师前缀比较条件分布：

\[
R(\theta)=\mathbb E_{H\sim D_A,\,A^0\sim\pi_0}
\sum_j D_{\rm KL}\!\left(\pi_{0,j}(\cdot\mid H,A^0_{<j})\;\|\;\pi_{\theta,j}(\cdot\mid H,A^0_{<j})\right).
\]

该条件KL和给出联合前向KL的蒙特卡洛估计；强制单选因子为零。它不同于在学生前缀上计算教师CE，也不同于现有带域归一和修改因素权重的`bcLoss`。训练在原PPO/价值/熵目标上加λR，保留E0部署温度，不经BC入口静默改成T=1。

- 两个模型看同一条**真实world历史**，各自推进hidden。参考建议不调用`ProgramController.apply()`，不产生平行教师世界。
- world中的槽位、任务、队列是学生实际状态；例如当前槽3为screen，参考KEEP也表示保持screen，不能用教师旧对局里槽3的harvest含义解释。
- 冻结参考的hidden可以预计算；学生锚点的历史条件用当前权重重建。计算成本归入P，不称免费。
- 锚点一半来自预先按地图/对手/阶段选择的C0完整来源，一半来自本轮学生实际轨迹；先选来源再看胜负，不拼接不同教师的生产、任务、成员标签。
- 用单独锚点微批次，初始有效帧量约为RL的四分之一。两部分按各自有效帧平均，加权后共同裁剪、**一次Adam**；教师动作不进入PPO行为概率或优势。
- 只校准一个正λ与0比较。可在P−第8步端点用固定序列，把保持梯度的工作量级设为actor梯度约10%，排除critic，并检查极端批次。C0复制点梯度为零，不能在那里做比值；任何分母近零都不能用大系数补救。
- 若P＋无必要，采用更简单P−；若保持项压掉可复验收益，最多一次减小权重复核。后续有持续净收益时减弱约束，避免永久锁住父策略错误。

已核对当前条件解码和GRU数据流，并用小型离散分布检查联合KL与教师前缀分解恒等式；这是数学/源码可行性检查，不是新训练或行为验收。

## 4. 评测先处理可比性和潜在相关性

已核实SDK的offline初始化使用gameId字符串`0`和秒级`Date.now()`；PRNG种子由二者组成。同秒并行创建可能复用随机源，**实际重复率尚未核验，也未证明其导致历史评测反转**。

先轻量读已有回放头的初始化标识、地图/规则、时间和实际出生：区分名义局数、不同初始化来源与疑似同源簇。同出生不等于同随机源，同随机源不等于同轨迹，回放文件SHA不同也不证明独立。

确认共享初始化时，以来源簇而非逐局进行不确定性估计；没有足够标识就报告创建秒的相关性敏感性，不能虚构精确有效样本数。新确认批次交错安排C0/候选和方法，统一repeat、swap、策略随机流，必要时仅对初始化节拍错开，游戏仍并行。当前没有已验证reset(seed)或中盘恢复接口。

筛选、复验、最终确认使用不同对局及创建簇。完整局保留Supalosa、两条0.1.16、旧强MC83，同代成绩另列。初始与候选在同一新协议下重评，旧结果不改写、不直接拼接。

约10个百分点只可作为初次样本量规划尺度，不作硬准入门槛；较小但独立重复的收益也应保留。行为证据用于解释经济/生产/作战是否实际衔接，不写成新的行动奖励或矿车禁令。

## 5. 策略空间搜索S只在条件满足后扩展

不立即把S升为主方法。P在合理覆盖下仍无净进展，或有限S预检已发现可复验候选时，才分配正式比较预算。

最小S用已有小模型产生少量解码参数变化，候选权重整局固定、仍按状态反馈并随机采样；PPO的权重在采样局中也固定，因此“固定参数”本身不是S优点。S改变的是候选生成与跨局选择方式。

初始冻结输入编码、world0、GRU和critic，限定解码层做小规模rank-1正负扰动，覆盖生产与任务/成员联合变化；不带兵种、地图或打法名称。先四个方向、正负八候选，按各动作族行为距离校准尺度，不能让成员变化掩盖生产仍完全不变。

只有“不变”或“整体失去基本玩法”的候选，说明该生成器在当前子空间/配额下无效；先停止，不加大型搜索框架补救。少量筛查后最多两份候选进入独立复验。候选本来就是可部署的小模型时，直接保留；只有明确需要合并/恢复能力才另外研究吸收，避免无目的蒸馏。

P/S正式比较从共同起点分叉，匹配全流程核小时及新局上限，包括S筛选、P锚点重放、所有失败与确认成本。

## 6. 顺序、里程碑和条件性墙钟计划

| 阶段 | 产出 | 后续决定 |
|---|---|---|
| 起点与样本核查 | 预定E0/B0、初始化来源核查、统一评测协议 | 只有重复基础能力损失才有界恢复；不开始无限教师迁移 |
| 初次6–12小时校准 | P−/P＋学习深度曲线、实际吞吐/内存/日志增长、保持项是否必要 | 选择能保持基本行为且确实利用更多经验的档位，不挑偶然最高分 |
| 滚动到24小时 | 固定配方、主线/压力各独立重复、连续新on-policy批次与能力复验 | 工作目标至少四块新采样、累计至少两批归一覆盖；退化/资源边界优先，不以单次小分差早停 |
| 条件触发S | 有意义候选生成、独立确认 | 无效则停S；有证据再做P/S正式比较 |
| 24–72小时分流 | 哪条路线能形成并保留净收益、可玩的冻结候选或明确反例 | 按证据继续/更换机制；不原样重复无信息失败，也不要求用满窗口 |

上述为实际墙钟的规划检查点，包含工程和等待，尚非实测交付承诺。首段测得窗口/核小时、游戏/核小时、锚点历史重算成本后再更新24/72小时预测。首期P−/P＋是两种优化配方；锁定后不把它们和S一起铺成三套长期大实验。

学习块内冻结对手；早期方法比较用同一冻结集合，随后保留main/pressure共同演化与固定强控制。保存current、独立确认版本和产品版本；停止结论针对本次预算/方法，不宣称收敛。实际训练步数、有效帧、独立来源、复用量和CPU费用都入记录。

研究里程碑要求相对共同起点产生可复验净收益；玩家默认的晋升还需与稳定0.1.16比较。可提供明确标识的研究候选，不把较弱起点的改善自动当成新稳定版。新原生批量目前只验证了离线AiPlayTurnManager的结算时序，图形客户端需另外核验；进入、操作、结算/退出及重开仍需验证。
