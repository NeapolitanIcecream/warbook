# 有效防守与火力覆盖：玩家复查后的修正计划

2026-09-17。用户观看两份失败回放，并补充第二份 9:50 的截图后制定。**本次是源码核对、定向参考和规划，没有改策略或启动新比赛。** 默认 0.1.7、阵地挑战者 0.1.8 与两份观战记录继续保留。

随后用户要求先改进分析方法；[分析工具](analysis-tools.md) 已按这两份反例完成改造。下列防守策略修改仍待实施。

## 1. 玩家指出的基本原则

防守必须实际保护建筑、矿车和作战力量：根据来袭方向提前占据能接敌的位置，受到攻击时调动守军参与反击，并根据局势更新位置。到达一个固定坐标、部署若干步兵，都不构成防守目标已经完成。

大兵部署属于战术动作。进入适合射击的位置后部署以增强火力，目标离开射程、接敌方向改变或需要支援时解除部署并移动。步兵不能被永久锁定在岗位上。组织部队的核心是让更多存活单位同时有效开火，避免有十个单位却轮流只有一个参与战斗；这个原则也适用于坦克集群与移动射击。

用户认为现有坦克碾压表现好。该能力保留为具体的战术资产，今后的防守调动应让它更容易发挥作用；新调度仍须遵守显式碾压权限和任务归属。

## 2. 已核对的失效链

### 当前阵地实现

- `BastionStrategy` 优先采用首次记录的矿车远离基地位置作为方向，此值可以一直压过后来出现的敌情；首次敌军方向本身也只记录一次。随后按基地偏移生成岗位，有工事时又绑定到实际工事附近。这些位置没有持续接受接敌效果检验。
- 护援只检查矿车、矿场、建造场周围的可见敌军，遗漏重工、兵营、电厂。动态 `responsePost` 只传给车辆，`base-garrison` 步兵始终使用旧 `post`。
- `PositionTactics` 的步兵跳过局部目标选择，按固定偏移移动，到岗便部署。代码已有解除部署分支，但它由“离岗位过远”触发，没有根据当前射击机会决定移动与部署。
- 近处威胁消失一段时间后，车辆重新收到旧 `post`。临时失去可见接触没有清除关于来袭方向的证据，却会把刚接战的兵送回错误一侧。
- 当前回报主要记录到岗、部署数量，不能回答这些单位是否保护了目标或参与了射击。此前按四车/六车/八车试验的重点过早落在参数上，未先纠正这个行为缺口。

## 4. 实施顺序

### A. 让守军实际接战，并完成动态部署

1. 防守目标包括关键建筑与矿车；用己方可观察的受损、可见来敌位置和接近方向确定需优先保护的对象。未知攻击者保持未知，不借裁判信息补齐目标。
2. 战略给出保护对象、威胁区域和可调用兵力。步兵、预备车辆及需要中断其他任务的部队由战略统一改派；护援不必等待反击坦克数量凑齐。
3. 战术先选择能攻击当前威胁的位置和目标。大兵按“移动接近 → 进入有效射程后部署 → 维持射击 → 需要换位时解除部署”行动。给已有有效火力保持射击的机会；避免不断切换部署状态或重复移动打断开火。
4. 反击、追击、撤回和重整使用当前防守需求与接敌方向。失去短时接触后保留方向判断，重算有用的待机位置；不自动回初始矿车方向或旧固定点。

先在现有战略/战术/协调器内完成这条链。生产经济保持冻结，坦克近距碾压继续复用。战略负责调多少兵保护什么，战术负责如何接敌和部署，单个单位仍只有一个任务所有者。

### B. 让待机位置提前覆盖可能的接敌面

- 利用公开地图信息、已探索地形、已知建筑布局，以及已确认来袭方向，选择我方一侧可到达的接近路线与入口附近位置。首次采矿方向只提供经济位置，不能决定所有守军的朝向。
- 对手尚未出现时，用可能起点与地图通路做有边界的预判；出现实际来敌后更新，不能将“暂时不可见”当作方向信息归零。
- 复用固定引擎的地图与路径能力。当前观察 DTO 尚未提供战术地形与武器射程；只补本项决策必要的合法地图摘要、己方武器信息，路径查询不得反向泄漏隐藏敌军或未允许的动态障碍。
- 同一威胁方向上的不同单位寻找能形成共同火力的位置；允许已能开火的单位先工作，其余单位继续进入射程。避免把部队压成一列、在建筑后堆积，或为满足几何阵型把正在开火的单位拉走。

预判布阵和受到攻击后的护援都要实现；A 先消除已看见攻击却不响应的错误，B 随后减少防守开始过晚与到场顺序不良的问题。

### C. 通过实际行为决定后续坦克战术工作

更新后的分析已确认第二份在 10:34 为六辆车发出进攻计划，11:10 采样到离开基地 12 格范围；12:00–21:20 六辆主力的采样坐标停在原处 1 格内，47 条移动命令与零坦克开火信号并存，整局敌方非防御建筑掉血与摧毁事件均为零。Computer use 在 13:53 看到坦克聚在敌基地外山崖旁，建筑位于另一侧。

因此当前优先检查短途行军目标的可达性、路径选择及无进展时的恢复。历史移动实现会按到最终目标的直线方向生成短途点；这与画面相符，但尚未用修复对照证明全部后果。不能把“没有形成有效攻势”直接写成“没有发出进攻计划”，也不再优先归因于军队规模。基本防守与行军有效后，再安排有限小队、汇合和机动射击。

你的坦克集群、火力保持与承伤经验继续作为目标。前出承伤要与压制攻击者同时发生；是否吸引敌火由实际目标选择验证，不能把部队移到建筑前就当成会自动拦截射弹。

## 5. 只做能改变决定的验证

1. 先用上述真实观察检查候选会不会调动守军、解除无用部署、保持正在发挥作用的火力。离线重新决策只能检验命令选择，不能宣称改变旧回放的结果或具备回放接管能力。
2. 普通零起始单位新局中观察完整的移动、部署、开火和再次移动过程，保留正常结束与上限。首批使用短图与小镇，对冻结 Supalosa 和旧 0.1.7，同时运行原阵地版与候选；执行前写定局数、出生位置覆盖要求和停止预算。
3. 判断修复首先看：建筑受击后守军是否及时参战；交火时有多少单位实际开火；敌情变化后是否无效归队；失去威胁后是否能恢复生产和进攻。复用现有日志和回放，若射击人数确实无法判断才在已有分析中补窄用途记录，不新建评分平台。
4. 实际射击与仅在几何射程内分开，攻击命令次数与参战人数分开。火力覆盖诊断不替代原胜负规则；保留部署反复、追敌失位、守军缺席等反例，即使该局最终获胜。
5. 修复行为成立后扩大完整局比较，按实际出生位置列出覆盖，避免再次把失衡的小样本解释为策略因果。没有预设全图必胜或任一组件必须提高胜率的结论。

完成标准：新回放中能看到部队提前站在有作用的位置、敌袭时参与反击、部署随接战调整、后排兵力进入火力范围；同时完整局和玩家入口保持可用。到岗人数、部署人数或更多胜于旧弱基线的局数，单独都不构成这一标准。
