# 战略发现能力：接口、表示与学习起点

2026-09-23 晚。审计版本 `5077a0a04790c6df97bdccfae913154d620dcba9`。本次为用户要求的研究讨论与代码审计，没有变更策略、训练数据、奖励或运行中的六线路实验；家庭网络无法访问训练服务器是已知正常情况，夜间结果仍待收取。

## 设计要求

用户建议用经典打法检查学习方法的能力空间。法国冰天迁移基地、利用中央富矿与巨炮防线，是人类研发侧的一个思想实验。**这个例子不进入策略示范、专用奖励、手写完整选项或针对性训练课程。** 通用引擎能力、公开规则与一般操作语义可补齐；如果未来人类示范中包含该打法，结果只能支持模仿/迁移，不能据此宣称自主发现。

已被研发阅读并用于调整架构的例子属于开发检查，不能继续叫未见评测。也不要求模型照抄每个经典开局：规则、地图、对手和预算不同，合理替代打法同样可能有效。

按四层解释结果：

1. **可表达**：合法观察、行动接口和配置能容纳这类行为。
2. **可执行**：从请求到游戏实际效果的链路完成。
3. **可发现**：有限训练中出现有意义的连续尝试，并获得可区分的结果。
4. **可保留**：更新提高成功率，后续训练没有抹去有用能力。

检查前两层可明确找出工程问题；后两层必须有训练和对局证据，不能由softmax概率非零、组件名称或更多对局数推导。

## 与AlphaStar相比，缺什么

目前已实现16维公开类型embedding、共享实体/区域/产品编码、128维GRU及条件化动作头。上一轮Pro第5次讨论明确推荐了实体/地图输入、小GRU和连续序列训练，第6次审查还发现并修正了训练与上线记忆不一致。不是完全没考虑表示与时间。

2019 AlphaStar的实体self-attention处理对象间关系，LSTM处理跨时间记忆，scatter连接融合实体与空间；自回归动作参数通过编码传给后续头。图中的embedding不意味着“每个MLP前都必须额外加一个模块”。参见[原论文](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf)。2023 Unplugged公开实现另有版本范围，不混作2019原模型。

本项目的具体差距：

- 每类图只有一次邻居均值汇总。区域表示经mean/max压入全局摘要后，目标头不直接取得对应区域的图编码；落点头也缺少对应局部空间/实体表示。
- 生产队列条件化前面的选择，任务/单位则不是完整串行协调；单位归属没有显式观察本次已分配的其他成员。
- GRU持续携带记忆，但当前训练块16步，梯度在块间截断；持续记忆不等于已学会分钟级的计划保持。
- 当前全计划PPO将多因子logp相加后统一计算ratio和裁剪。数学上不是错误，但因子变多时可能更敏感；需测实际clip/KL及有效更新，不能以公式检查代替强度结果。

四份本地v2数值校验样本中，非强制条件选择数为27/36/25/26；开局仅一辆MCV的状态也有27项，含16任务槽。它们不等于实际提交命令数。私有证据：`work/consult-pro/strategy-discovery/factor-count.json`，包含输入SHA。这支持检查输出组织方式，不证明PPO瓶颈已归因。

值得优先比较的是直接保留区域/实体与目标的关联，再与小型attention、同预算更宽网络区分。没有证据要求复制大型Transformer，也没有证据证明约32万参数已经足够。

## 初始策略：不把手写更多整套战术当主路线

[AlphaStar官方说明](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)强调强且多样的监督起点，以及后续对人类策略多样性的保留。我们从少数规则路线起步，不能据此期待同等的探索起点。

一次同池对照中，规则主线21/32、显式教师16/32；另外的学习评测中学生各0/32。两批结果不直接相减，但说明不能只用老师强度解释学习失败。需要分别解释：

- 规则经新接口的行为投影/频率为什么损失能力；
- 模型为什么没有学稳老师已经拥有的行为；
- 老师根本没有展示过的能力如何获得正向探索起点。

规则方法的保留价值是可靠的操作闭环、基础示范和固定对照。历史Supalosa审计已经说明其有任务/小队/经济/地图模块；没有原版RA2简单电脑的同条件结果，不能把“极简状态机更强”当已验证事实。也不能因为这一点回避我们历史上的控制冲突和基础行为缺项。

优先方案是补齐通用可执行能力，整理少量来源多样且可学的示范，配合一般技能课程；人类数据先核实引擎版本、合法观察和动作映射，不承诺现成大数据集。强化学习阶段需要能持续完成一个有意义的尝试，而不只在很多头上逐步随机改动。更稀疏的计划编辑、学到的持续意图和成功轨迹保留，均属于可比较候选，尚未实施；不得偷偷写成经典套路选项。

## 经本地复核的Pro补充

完整回复已收取。Pro按固定ref读取22个文件，本地抽查网络、训练器、世界编码、桥接器、运行器的5个Git blob SHA一致。它未运行引擎、未取得私人权重/资源或今晚结果；代码审查不计实验胜利。

新增核实的调度缺口：`next_learning_state`只以聚合胜场决定BC→PPO；16场检查中的4胜有可能全来自当前弱同伴。进入PPO后阶段不会自动退回。旧模型保留机制仍存在，不能误写为完全没有回退，但需要分开基础能力、分对手成绩和所处学习阶段。最终固定池也未包含当代main/challenger交叉矩阵，收取时应补充这一比较。

推荐的学习对照：

- 在启动不稳时比较普通教师前缀逐步缩短与现状。前缀真实从开局运行、不假设restore；只把模型接管后的动作计入自身RL，始终保留零前缀完整局。
- 在自身已有可重复成功时比较成功轨迹保留/小量一般能力锚点与当前PPO。可参考[SIL](https://proceedings.mlr.press/v80/oh18b.html)和[AWR](https://arxiv.org/abs/1910.00177v3)；它们复用已有有效行为，不会凭空创造未探索到的策略。
- 保留一个不同的探索候选：对小量适配参数或未赋予人工套路含义的潜变量做整段持续扰动，再用完整局筛选、复验与蒸馏。不是随机搜索全部参数，也不是命名几个手写开局；[已有StarCraft研究](https://arxiv.org/abs/1609.02993v3)的证据范围为局部微操，不能冒充完整战略成功。
- 每域裁剪并不等价于原联合PPO，不能当作无偏的bug修复直接替换；必须单独比较漂移和实际收益。

接受这些问题和实验候选，不照搬所有日程默认值。Pro建议固定留15.5小时最终评测，缺乏本项目新模型吞吐依据；实际收尾余量应由明日测得的评测规模、墙钟时间及故障恢复余量决定。

## 明天与假期实验

25–27假期；24日17:30至28日09:00约88小时，用户授权按实际需要部署独立长任务。预设作业不依赖开发机在线，中途分析、修复和改变方案才需要可访问的Agent环境。

1. 先收六线路；若基础建设和任务仍失效，定位最早实际分叉、教师/模型任务语义及更新，而不原样延长失败训练。
2. 一般接口能力检查与新模型设计可以继续推进，不要求每个旧子项先显著赢基线才扩权。
3. 优先选择一个明确干预做同起点/同数据或同CPU预算对照；控制权范围保持一致。需要新编码时明确转换范围，不能挪用旧PPO行为概率。
4. 有稳定完整局能力后，分配主线/挑战者的持续学习、较强历史对手保留、独立重复和固定参考评测。保留学习过程中的能力，不只挑一个总胜率冠军。
5. 课程解决短反馈和基本行为组合，最终完整局仍单独验收；来源、失败、时限及数据空间边界继续记录。
