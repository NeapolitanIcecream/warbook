# 0.1.16：保持原生命令、矿车脱险与矿区屏卫

2026-09-20。学习架构讨论已保存到 [接入边界](learning-boundary.md)，真正迁移时再做详细推演；本轮交付规则基线。过程、原型和负结果见 [迭代记录](iteration-016.md)。

## 三项实际行为

1. **保持原生命令。** 攻守、侦察、屏护和工程师共用物理命令身份；同一命令不再仅因计时到期而重新提交，内部任务标签也不会打断它。观察到空闲且任务仍需执行时允许重试；目标改变、部署切换和紧急撤离保留明确下令。正在开火的单位不会因已经抵达驻点而被 Stop 打断。完整移动仍由原生 Move/AttackMove 执行。
2. **矿车遇袭返矿。** 己方 HP 下降触发原生 Dock，选择己方可用矿场并优先避开当前可见火力。保持引擎返矿/传送/卸矿任务；空载返抵后选择安全矿点恢复 Gather，无合适矿点时暂候。恢复采矿同时检查目的地和直达通路的可见火力，避免刚脱险就穿过同一敌军。该保守检查不是完整动态避敌寻路。
3. **屏卫随作业矿区转移。** 以己方载矿量增长定位实际作业区，短暂卸矿和传送不把驻点拉回基地。坦克在矿区朝敌方来路的一侧集结；兵力允许时保留两辆装甲作独立屏卫，其余主力继续行动。原生路径与独立地图提示落实可达位置，已探索矿点不再局限于旧的基地前方距离窗口。

真实动作试验 `runs/miner-return-probe-clear`：盟军矿车 5480 tick 遇袭、5481 请求 Dock，发生一次跨距传送，5524 空载返抵、6324 再次装矿；苏军矿车 7617 遇袭、7982 返抵、8583 再次装矿，没有遇袭后的传送。是有实际敌军开火的界定时段试验，不计完整局胜负。己方 cargo 来自公开 UnitData，未读取隐藏攻击者。

完整局中的转场例：`strategy-016-mining/mp06t2.map/old-defense/0-integrated-016`，驻点从 (47,87) 转到 (68,70)，随后两辆坦克实际到达且矿车继续装矿。到达与存活是行为证据，不冒充独立战斗收益归因。
