# 对局分析：先看行为，再解释原因

2026-09-17 更新。用户指出两个一眼可见的失败：部署守军没有支援受击建筑，主力攒了很多坦克却没有形成有效攻势。原首车工具给出了开火、受伤、被毁时刻及大量逐帧数据，却没有首先回答这两个问题。本轮直接重写现有 `analyze:encounter` 的默认分析，不新增分析入口或评分系统。

## 当前工作流程

1. 批次报告用于选择值得检查的对局；单局先输出一页行为摘要。
2. 摘要出现停滞、守军缺席或无法解释的交战时，直接用 computer use 看相应时段，检查地图通路、站位、部署与进退。使用临时页面，检查后关闭。
3. 用最少的命令、位置或源码核实画面上的解释。确需逐帧资料时，指定一个时间窗口；一次观看即可解释的问题不扩成新的统计平台。
4. 根据具体失效做小改动和真实对照。界面动作、提交命令、实际交战与完整局结果分别支持不同结论。

## 默认摘要回答什么

- **是否计划进攻？** 首个有兵力的主力进攻任务，以及归属该任务的作战命令。按协调器 `origin.id` 归属，不能依赖可选的人类任务标签；旧版本没记录计划时标为未知。
- **部队是否行动？** 用已有位置快照对照持续行军任务，指出目标未到达、同一批坦克长时间停在原处却仍收到移动命令的时段。离开基地范围只证明位移，不冒充已经攻击敌基地。
- **实际打到了什么？** 回放检查敌方非防御建筑的掉血与摧毁事件，区分进攻意图和实际影响；伤害不擅自归属攻击者。
- **守军是否参与？** 用固定半分钟窗口对照己方建筑受损、附近可见地面威胁、存活/部署步兵数与开火信号。优先展示最早的无步兵开火窗口，避免后期敌军打到旧岗位时的开火掩盖早期缺席。

射击使用已验证的同武器冷却重启信号，并同时检查主、副武器，使部署大兵的 Para 不再被漏掉；两秒内不同开火单位数是火力参与的诊断。几何射程内人数不代表射界检查通过，也不代表实际开火。保留这些界限，不用指令次数或部署人数替代交战。

对第二份执行了 computer use 复查：13:53 的画面显示六辆坦克聚在敌基地外山崖旁、建筑在另一侧。结合源码直接朝目标生成短途移动点的做法，下一项缩小到路径目标可达性与无进展恢复；尚未用策略修复证明唯一原因。临时页已关闭。

## 输出与实现的收缩

原默认首车锚点、全部射击/受伤区间、局部引用到原生 ID 的映射和自动逐帧窗口，退出默认分析。由已有日志负责计划/位置检查，由一次回放重建负责交火/受损与一致性核对；纯判断放在 `src/analysis/match-behavior.ts`，入口仍是 `scripts/encounter.ts`。

第一份同一回放的旧默认输出为 JSON 13,907 字节、Markdown 948 字节、窗口 68,287 字节，合计 83,142 字节；新默认摘要和 JSON 合计约 3.9 KiB，默认不导出帧。旧首车明细仍可从 Git 和既有本地记录追溯。输出量显著减少，但新旧提取内容不同，不据此宣称执行速度提高。

四份验收、默认输出成本及反例检查存于本地 `work/analysis-validation/results.json`。运行成本按每次报告记录；没有新增依赖。

```sh
# 一页摘要，默认不产生逐帧文件。
npm run analyze:encounter -- runs/<single-game>
# 摘要和画面仍不能解释问题时，才选一个明确窗口。
npm run analyze:encounter -- runs/<single-game> --window 7200:7500
# 可以指定 actor，或额外检查某个控制任务/历史标签的命令。
npm run analyze:encounter -- runs/<single-game> --actor WarbookBlue --task main-force
```

## 保留有实际用途的原方法

`npm run analyze -- runs/<batch>` 继续复算冻结双方身份、完整启动台账、直接对战、镜像、停止类别和实际出生覆盖；不改原胜负规则，不自动重加权或晋升。Clopper–Pearson 区间只说明独立二项假设下的不确定性，不解决选择偏差或出生不均衡。`production_events.py` 继续服务于第四到第五辆坦克的补兵问题，不混入每份默认摘要。

本轮检查：55 项 TypeScript 测试、8 项原批次分析测试、类型检查和构建通过。新增测试覆盖计划与执行混淆、缺失日志、缺失任务标签、移动/观测缺口、部署副武器开火、建筑类别及实际终态。相关历史验收见 [原分析记录](https://github.com/NeapolitanIcecream/warbook/blob/35ff48d/docs/analysis-tools.md)。
